让 AI 从“会聊天”
走向能协作、能办事、可管理

Agent Platform 是面向企业和软件公司的智能体运行底座。它把多个 AI 专家、业务流程、知识资料和外部工具组织起来，在权限与审批约束下完成实际工作，并且让过程可追踪、结果可审计。

了解系统架构 ↓看看能解决什么问题
多智能体协作工作流编排工具安全治理企业级多租户私有化部署
01 / WHAT IT IS

先用一句大白话讲清楚

把它理解成一家数字化公司的“AI 操作系统”：不是单独一个聊天机器人，而是一套能安排 AI 员工、分配任务、提供资料、调用工具、检查过程和记录结果的基础设施。

🧠

AI 专家团队

不同 Agent 可以扮演不同岗位，例如研究、分析、执行、审核。它们围绕同一个任务协作，而不是各聊各的。

🗂️

统一工作台账

项目、任务、运行记录、资料、决策和证据有明确归属。工作进展能够沉淀，不只留在聊天窗口里。

🛡️

带护栏的自动化

AI 可以处理授权范围内的工作；涉及对外发送、资金或权限等高风险操作时，必须按规则审批或由人执行。

02 / TECHNICAL ARCHITECTURE

技术架构：每一层各司其职

系统采用分层、模块化设计。入口层接收请求，控制面管理身份和权限，编排层安排流程，运行时执行 Agent，黑板共享协作信息，工具网关控制外部操作，底层负责数据与事件。

03 / CAPABILITIES

平台具备哪些技术能力

以下是平台的能力版图。具体模块的交付状态以代码、测试和部署验收为准；架构设计覆盖不等于所有能力已经全部生产化。

01 · IDENTITY

多租户与权限

不同客户、组织和团队的数据与操作权限隔离；通过角色和资源范围控制访问。

02 · AGENT RUNTIME

智能体运行时

统一 Agent 的执行入口和上下文，运行引擎通过适配层接入，避免平台被某一个模型或框架锁死。

03 · ORCHESTRATION

工作流编排

把复杂工作拆成步骤，支持条件分支、并行处理、等待人工确认和中断后恢复。

04 · BLACKBOARD

共享认知黑板

专家共享事实、证据和观点；可以提出质疑、登记冲突并形成有依据的决策，不靠聊天记录碰运气。

05 · TOOL GATEWAY

工具与 MCP 安全网关

统一接入外部工具，按租户、角色、Run 和工具白名单授权；高风险动作绑定一次性审批。

06 · KNOWLEDGE

知识库与检索

管理文档、版本、切片、索引、访问控制和来源引用，让 Agent 能基于企业资料回答和工作。

07 · MEMORY

记忆与上下文

管理跨会话可复用的信息，并区分对话历史、任务运行状态、知识资料和共享黑板。

08 · GOVERNANCE

评测与治理

通过评测集、回归检查、权限策略和审计记录，持续检查 Agent 是否按预期工作。

09 · COST & QUOTA

配额与成本管理

按租户、模型或任务约束资源使用，跟踪 Token、延迟和调用成本。

10 · OBSERVABILITY

运行可观测

追踪一次任务经过哪些步骤、调用了什么工具、哪里失败、消耗多少资源，方便排障。

11 · RELIABILITY

事件可靠性

通过持久化事件、重试、幂等回执和死信处理，降低异步任务丢失或重复处理的风险。

12 · EXTENSIBILITY

扩展与部署

通过声明式扩展包和版本化接口增加行业 Agent；支持私有部署、迁移和灰度切换的建设方向。

04 / USE CASES

它具体能帮企业干什么

平台提供通用底座，实际业务由行业 Agent、工作流、知识资料和授权工具组合出来。

接收目标用户提出需求、上传资料或创建任务
拆解工作编排流程，分配给不同专家 Agent
协同分析查知识、共享证据、交叉检查
受控执行调用授权工具；必要时请求人工审批
交付沉淀输出结果、记录过程、形成可追溯资产

企业 AI 客服

检索产品知识和客户记录，判断问题类型，生成答复草稿；退款、改账等动作按权限交由人工确认。

研发与项目管理

拆解需求、整理 Issue、分派任务、检查交付证据、汇总进度，让项目过程透明可追踪。

行业知识助手

把企业制度、产品手册、业务资料接入知识库，让专业 Agent 按来源回答并形成分析报告。

运营与流程自动化

串联内部系统和外部工具，自动完成低风险步骤；关键发布、通知和数据变更保留审批关口。

多专家研究分析

让多个 Agent 从不同角度研究同一问题，交换证据、挑战结论，再汇总成有依据的判断。

软件公司交付行业产品

在统一底座上配置品牌、行业知识、角色和流程，形成可复制交付的垂直领域 AI 产品。

06 / DELIVERY BOUNDARY

哪些已经有基础，哪些仍需持续建设

我们不把设计蓝图说成已经全部上线。仓库同时保留轻量旧工作台，并在 agent_platform/ 中建设生产级平台模块；新平台依赖单独安装，基础设施接入按阶段推进。

仓库已有实现基础

核心模块与安全机制

已建立平台模块边界、共享契约、PostgreSQL 迁移体系，以及黑板、工具网关、事件可靠性、租户身份等模块的实现与测试基础。

持续集成与验收

端到端运行链路

LangGraph、Harness、MCP、数据库与事件设施需要在具体部署环境完成组合验证；不同运行适配器的质量和成本仍需基准评测。

按阶段生产化

部署与运维闭环

控制面服务化、多实例路由、真实模型接入、完整 UI、故障演练、监控告警和迁移回滚，需要逐项完成生产验收。

特别说明：平台架构目标包含多租户、私有部署、SaaS、灰度迁移等企业能力，但实际可用范围取决于当前部署版本和已完成的验收项。不要仅凭本介绍判断某项功能已在生产环境启用。
07 / PRODUCT VALUE

最终带来的价值

对业务团队

把重复、跨系统、需要多角色协作的工作流程化，减少人工搬运和信息遗漏。

对管理者

看得到任务进度、执行过程、资源成本和审批记录，出了问题能定位、能追责、能复盘。

对软件公司

底座能力复用，行业能力差异化；不必每做一个 AI 产品就从权限、运行时和工具治理重新造轮子。
