# 交付方案｜龍奕FDE工作室 Agent 组织 v1.2

- 项目：OPC-001
- 版本：v1.2（事件驱动版，替代 v1.0 时间表版本）
- 目标：8 个 Agent 以事件驱动方式，同时支撑客户交付与公司运营。

---

## 1. 核心原则

1. **事件驱动，不排班。** 没有"每天 09:00"，只有"事件发生就响应"。
2. **每件事都有开始时间和关闭时间。** 没有关闭标准的事，不进日程。
3. **Agent 只起草，人做承诺。** 对外发送、报价、签约一律人工确认。
4. **所有输出留痕。** 每个事件的处理结果写回台账。

---

## 2. 事件模型

每个事件必须有五要素：

| 要素 | 说明 |
|---|---|
| 事件名 | 发生了什么，一句话 |
| 来源 | 客户、项目、任务、组织、学习 |
| 开始时间 | 什么时候开始处理 |
| 关闭时间 | 最晚什么时候必须有结果 |
| 验收证据 | 什么算完成（文件、链接、签字） |

事件五类：

- **项目事件**：立项、里程碑到达、里程碑偏离、验收、上线、事故。
- **任务事件**：创建、开始、临期、逾期、阻塞、关闭。
- **客户事件**：新线索、诊断邀约、访谈完成、报价、签约、付款。
- **组织事件**：负荷超限、能力缺口、招聘启动、试用到期、解约。
- **学习事件**：引入新工具/新工程、首次执行某类交付、客户问题答不上来。

---

## 3. 事件 → Agent 响应表

| 事件 | 响应 Agent | 输出 | 人审 |
|---|---|---|---|
| 任务创建 | 秘书 | 补齐五要素 + 排入日程 | 缺要素退回 |
| 任务开始前 1 天 | 秘书 | 开始提醒 + 前置条件清单 | 否 |
| 任务临期（关闭前 2 天） | 秘书 | 催办 + 阻塞排查 | 否 |
| 任务逾期 | 秘书 | 逾期升级，每天最多 3 次 | 否 |
| 任务关闭 | 秘书 | 验收证据检查，关闭或退回 | 否 |
| 项目签约 | 产品经理 + 幕僚长 | 需求说明、方案初稿、确认计划 | 是 |
| 方案获客户书面确认 | 规划师 + 秘书 + 教练 | 项目计划、WBS、排期、能力准备清单 | 是 |
| 需求变更 | 产品经理 + 规划师 | 影响评估、是否重排 | 是 |
| 里程碑到达/偏离 | 幕僚长 + 规划师 | 态势简报、风险、待决策 | 是 |
| 出现阻塞 | 幕僚长 + 秘书 | 阻塞分析、升级建议 | 是 |
| 引入新工具/新工程 | 教练 | 使用指南 + 关键点 + 考题 + 验收标准 | 是 |
| 首次执行某类交付 | 教练 | 步骤指导 + 检查点 + 考题 | 否 |
| 客户问题答不上来 | 教练 | 补课包 + 话术 + 复测 | 否 |
| 验收未通过 | 教练 + 幕僚长 | 差距清单、重练计划、是否延期 | 是 |
| 项目完成/失败 | 内容 | 案例或失败复盘 | 发布前确认 |
| 管道线索不足 | 侦察 | 线索批次 + 打分 + 话术 | 触达前确认 |
| 负荷超 120% | HR | 缺口表、补法建议 | 是 |
| 事故/投诉 | HR + 幕僚长 | 复盘、流程与人员调整 | 是 |

## 4. Agent 规格（只列差异）

### 4.1 幕僚长

- 职责：态势判断、优先级、风险、决策请求、决策留痕。
- 触发事件：项目立项、里程碑偏离、资源冲突、阻塞、需要拍板、阶段结束。
- 输出：一页态势简报（发生了什么、影响、建议、待拍板）。
- 权限：A0/A1；不对外。
- 指标：关键事件 24 小时内出判断；决策可追溯。

### 4.2 秘书

- 职责：计划与日程的唯一入口，管开始时间、关闭时间、提醒与关闭。
- 触发事件：任务创建/开始/临期/逾期/关闭，日程变更，客户承诺产生。
- 输出：日程表、开始提醒、临期催办、逾期升级、关闭确认。
- 权限：A0/A1；不自动延期，不替人排优先级。
- 指标：任务关闭率 ≥80%；提醒零遗漏；无僵尸任务。

### 4.3 教练

- 职责：跟着交付任务走，给"做完这件事需要知道的最小集"，然后验收。
- 触发事件：引入新工具/工程、首次执行某类交付、交付卡住、客户问倒、验收未过。
- 输出：操作指南 + 关键点 + 考题 + 验收结论。
- 权限：A0/A1；未过不得进入下一题。
- 指标：每个新任务类型都有指南与考题；验收通过后才算交付完成。

### 4.4 商机侦察

- 职责：线索供给。
- 触发事件：管道有效线索 <5 条、新定位发布、进入新行业、诊断邀约不足。
- 输出：线索批次（对象、痛点、分值、话术）。
- 权限：A0/A1；不触达。
- 指标：有效线索 ≥5 条/周（按事件补货，不按天打卡）。

### 4.5 内容

- 职责：把交付变成信任资产。
- 触发事件：项目完成、项目失败、客户高频问题、里程碑。
- 输出：案例、复盘、短内容、demo 脚本。
- 权限：A1；发布需人确认。
- 指标：每个项目至少沉淀 1 篇内容。

### 4.6 HR

- 职责：组织缺口与补法。
- 触发事件：负荷超限、能力事故、新服务线、试用到期。
- 输出：缺口表、岗位包、评估与解约清单。
- 权限：A0/A1；录用与解约由人决定。
- 指标：缺口 1 周内出方案；人力成本 ≤月收入 30%。

---

### 4.7 产品经理

- 职责：需求采集与分析、方案设计、原型、客户确认、变更控制。
- 触发事件：项目签约、诊断完成、客户提新需求、方案被否、验收争议。
- 输出：需求说明 + 方案设计 + 方案确认单 + 给规划师的交接包。
- 闸门：没有客户书面确认单，规划师不得排期。
- 权限：A0/A1；方案讲解与发送需人确认；不承诺工期与价格。
- 指标：方案一次确认率；执行期需求变更率 ≤20%；验收争议为零。

### 4.8 规划师

- 职责：项目分析、WBS 拆解、排期、依赖与缓冲、变更影响评估。
- 触发事件：方案获客户书面确认、需求变更、里程碑偏离、资源冲突、项目关闭。
- 输出：一页项目计划 + 可排期的任务清单（交秘书）。
- 边界：不做公司级取舍（幕僚长），不排日程提醒（秘书），不做技能指导（教练）。
- 权限：A0/A1；不向客户承诺工期。
- 指标：计划一次通过率；任务按期完成率 ≥80%；变更 24 小时内出评估。

## 5. 计划与日程（秘书维护）

### 5.1 三类计划

| 计划 | 内容 | 条目示例 |
|---|---|---|
| 客户交付计划 | 诊断、方案、构建、验收、上线、运维 | 诊断访谈：11-12 开始，11-16 关闭 |
| 公司运营计划 | 招聘、学习、内容、财务 | Harness 部署：11-12 开始，11-18 关闭 |
| 个人学习计划 | 与交付绑定的学习任务 | Harness 考题验收：11-18 关闭 |

### 5.2 每个日程条目必须写清

- 对象（客户名/内部事项）
- 开始时间
- 关闭时间
- 关键节点（开始、临期、关闭）
- 前置条件
- 关闭证据

### 5.3 提醒规则

| 时点 | 动作 |
|---|---|
| 开始前 1 天 | 提醒 + 前置条件检查 |
| 开始当天 | 确认是否启动，未启动记录原因 |
| 关闭前 2 天 | 临期催办 |
| 关闭当天 | 关闭确认，检查证据 |
| 逾期 | 每天提醒，最多 3 次；超过 3 天升级给幕僚长 |

## 6. 教练：交付伴随（以 Harness 部署为例）

当"部署 Harness 工程"这个任务创建时，教练不是讲一门课，而是给四样东西：

**1）使用指南**
- 环境与依赖怎么装
- 配置文件每个字段什么意思
- 数据集要什么格式、多少条
- 运行命令与预期输出
- 报告怎么看：准确率、召回、拒答率分别代表什么
- 常见错误与处理

**2）关键点清单**
- 数据集必须来自真实业务，不能用编的
- 先跑基线，再改配置
- 每次改动记录版本，否则无法归因
- badcase 要分类，不要只数总数
- 上线判断看业务指标，不看跑分

**3）考题（从易到难）**
1. 独立跑通一次评测，交报告
2. 解释三个指标的含义与区别
3. 复现一个 badcase，说明原因
4. 改一个配置，预测影响并用数据验证
5. 给出"能不能上线"的判断和依据

**4）验收**
- 不看文档独立完成 1-3 题
- 第 4-5 题能讲清取舍
- 未通过：指出差距，重练同一题，不进入下一题

## 7. 人机分工

| 事项 | 人 | Agent |
|---|---|---|
| 定位与场景选择 | 拍板 | 提供选项与依据 |
| 客户关系 | 全部 | 准备材料 |
| 访谈 | 主谈 | 提纲、记录、报告初稿 |
| 需求与方案 | 客户确认 | 产品经理分析设计 |
| 项目排期 | 确认 | 规划师拆解 + 秘书排期 |
| 计划与日程 | 确认 | 秘书维护与提醒 |
| 交付执行 | 验收 | 教练指导 + 构建 |
| 对外发送 | 确认 | 起草 |

---

## 8. 验收标准

1. 每个任务都有开始时间、关闭时间和关闭证据。
2. 每个关键事件在 24 小时内得到响应。
3. 每个新任务类型都有教练的指南与考题，且验收通过。
4. 所有交付物按规则归档到飞书对应节点。
5. 对外发送内容 100% 人工确认。
6. 每个项目签约后 2 天内产出 WBS、排期与 20% 缓冲。
7. 每个项目排期前必须有客户书面确认的方案确认单。

---

## 9. 风险与边界

- **不做**：自动对外发消息、自动报价、自动签约。
- **不做**：固定时间打卡式提醒；只按事件和日程节点提醒。
- **边界**：Agent 输出默认是草稿，承诺由人负责。
