# FDE OPC 平台 · 坦率可用性评估

- 日期：2026-11-12
- 依据：[13-平台实测记录](13-平台实测记录.md)（命令、输出、耗时、token 均为实测）
- 评审口径：**对创始人有没有用**，不是"功能是否齐全"

---

## 一句话结论

**它是一个好用的"项目管理底座" + 一个合格的"文案/排期助理"，但还不是"替你干活的团队"。**

平台把"记事情、算进度、拆计划、查一致性"做到 0.1 秒级且可信；一旦要求它产出**需要外部事实**的东西（客户是谁、这周聊了什么、给我 10 条线索），它就会给你一份格式漂亮、标注齐全、但不能用的东西。

好消息是：挡住价值的不是架构，是三处很小的缺口（索引、正则、数据入口）。实测里补一行索引就让 `pm` 从"重造问卷"变成"发现真实冲突"。

## 二、真有用的（留着，天天用）

### 1. `plan`：一句话 → 一周排期　★★★★★

```
7.17s，5 条任务，都有人/有期/有完成标准，13h 在预算内
[OK ] #1 筛选3个高意向潜在客户并确认联系方式｜scout｜11-12→11-12｜2h
[OK ] #4 跟进客户并预约30分钟诊断时间｜pm｜11-13→11-14｜4h
```

这是全平台唯一"10 秒换 1 小时"的功能。创始人最缺的就是把目标拆成可执行条目，这件事它做得比手写快且不会漏依赖。

### 2. `auditor`：能挑出你自己看不见的毛病　★★★★☆

```
| T-0011 hours=16.0 | 数字无来源 | "16.0" | 工时数字无出处，未标注估算依据 |
| T-0011 done_when | 承诺越权 | "陌生客户 30 分钟出诊断报告..." | 属 S4 推断且未标注 |
```

两条我都回库核对过，**全对**。`hours=16.0` 确实没来源，`done_when` 确实是越权承诺。这是"多一双眼睛"的真实价值，而且不花钱（本地/订阅触发）。

减一星：结论写"整改后通过"，正文却列 3 条必改项，自相矛盾。

### 3. `brief` / `check` / `doctor` / `check_consistency`：底层可信　★★★★★

```
brief  0.09s → 未关 7 / 全部 30；需处理 3
check  0.10s → 3 条临期，排序正确
一致性 1.18s → DB ↔ 04 ↔ 09 ↔ 飞书 四方 90.0h/107 条一致
```

四方对账（数据库、项目计划、分项计划、飞书表）全部对齐，这不是"跑通"，这是**数据可信**。所有 Agent 的花活都建立在它上面。

### 4. `content`：唯一"改两个词就能发"的产出　★★★★☆

> 制造业老板，你的系统是不是越用越乱？
> ……我做的事：把散落的系统、表格、流程，整合成一套能跑通的交付体系。不卖软件，不卖课……
> 一个真实案例：……**[假设·S4：该案例为内部孵化项目，非外部制造业客户，具体效果待验证]**

3.91s、197 token。短、有观点、还自己标了假设。文案类活儿可以直接交给它。

### 5. 工作记忆六槽位　★★★★☆

实测：写一条 `constraints`（"问卷必须对齐 templates v1.0，不要另起一版"），重跑同一任务，**第二轮就不再重造问卷**，改为"直接引用 v1.0，不做任何改动"，并把报价单列为未决问题。

一次 `memory set`，抵十行 prompt。这是整套设计里最被低估的机制。

> 注意边界：它只是"服从约束"，不是"核对事实"。第二轮它写"与 v1.0 完全一致"，但它当时没读过那个文件。

## 三、半有用的（能用，但最后一步还得你自己干）

| 功能 | 卡在哪 | 你需要补什么 |
|---|---|---|
| `pm` 写 PRD/诊断包 | 补索引后能引用真实模板，但仍会补出不存在的结构（把"按结果定价"的报价单说成"按天计价"） | 逐条核对它引用的原文 |
| `planner` 排期 | 结构完整，但算术会错（"10h 含 2h 缓冲 = 12h"），状态全写"待确认" | 自己校准工时和依赖 |
| `secretary` 纪要 | 没有数据源，输出全是"无数据" | 先手工把记录贴进去（目前无入口） |
| 控制台派活 | 端到端能跑（R-0001 约 12s 完成），但产物路径不在页面上 | 自己去 `agency/outputs/` 翻 |

## 四、摆设 / 负价值（现在别指望，有的还在花钱）

### 1. `secretary`：接不住最日常的活

"整理本周潜在客户沟通" —— 这是创始人每周真会做的事。它的产出：

```
| 联系人 | 诉求 | 下一步动作 | 责任人 | 截止时间 |
|---|---|---|---|---|
| 无数据 | 无数据 | 无数据 | 无数据 | 无数据 |
```

**归因：不是设计问题，也不是模型问题，是数据问题。** `facts` 表 0 条，平台没有任何飞书聊天 / 邮件 / 日历 / 会议录音的导入通道。角色定义写得再好，没有输入就是空转。

> 讽刺的是：它的态度是对的——明确写了"请提供原始记录，不臆造客户信息"。所以它不会骗你，只是帮不上你。

### 2. `scout`：10 条线索 = 0 个真实企业

```
| 1 | 苏州某精密零部件厂 | 苏州 | 100-300人 | 质检记录靠纸质，追溯难 | 7 | S3+S4 |
| 2 | 无锡某注塑模具厂 | 无锡 | 50-150人 | 模具维修经验在老师傅脑子里 | 7 | S3+S4 |
```

**归因：没有联网检索。** 它只能按行业常识生成画像，再把画像包装成表格。还编了个不存在的文件让创始人去打开：

> "请创始人从 `company/名单.md` 中匹配真实企业"　→ 该文件不存在。

价值残值：10 条"痛点 + 开场话术"的组合可以当**销售话术库**用，但一条都不能当线索。

### 3. 事件总线 + 默认订阅：在为误报买单

```
审计：发现 4 处疑似无来源信息：
  - 日期 0-5 未出现在输入事实中
  - 日期 5-15 未出现在输入事实中
```

`0-5`、`5-15` 来自"0-5 分钟""5-15 分钟"。正则把时间区间当成月-日 → 产生 `audit_flag` → 订阅自动触发 `auditor:run` → **3 次 LLM 调用、约 7,600 token，换回三份"审计通过"**。

**归因：一个 10 行的正则 bug，被事件总线放大成了持续成本。** 机制本身是对的（26 条事件投递、失败单条隔离都正常），是默认开着的订阅在给噪音付费。

### 4. 单次输出 1500 token 上限

pm 第一轮 120 行产出在第 1,500 个 token 处被硬截断，报告模板只写到 `| 维度 | 现状 | 问题点 |` 就没了——但交付物清单上还打着 `✅ 定稿`。

**归因：`max_tokens: 1500` 写死在 `LLMClient.chat` 里。** 凡是"定稿一份文档"这类任务，必然断。

### 5. 操作层（gui / browser / probe / policy）

预检 3.78s 通过、策略能解释到来源、模型路由清楚——工程质量很高，但**今天没有任何一条真实任务需要它**。它是为"替你操作电脑"准备的地基，现在还不是产品。别在这上面继续加料。

## 五、为什么（三个结构性原因）

1. **公司最值钱的资产没进索引。**
   初测时向量库 89 块全部来自 `clients/002`，`company/`（定位卡、客户画像、宪法）和 `templates/`（五件套）**一块都没有**。Agent 看不见你的方法论，只能凭常识重造——于是重造出一个比现有模板更差的问卷。

2. **Agent 没有"输入端"，只有"输出端"。**
   台账能读（所以 auditor 准），文档读不到（没索引），外部世界读不到（没联网），飞书聊天读不到（没通道）。**能读的只有 160 字的检索片段**——于是它经常"半懂"，而半懂比不懂更危险（ps：把"按结果定价"说成"按天计价"）。

3. **没有"产出必须可核对"的硬约束。**
   四份产出里三份自称"定稿/已对齐/通过"，没有一份真正打开过被引用的文件。自评没有任何校验，等于没有自评。

## 六、最小改法（按"改动小 × 价值大"排序）

| # | 改什么 | 改多大 | 预期效果 | 怎么验证 |
|---|---|---|---|---|
| **1** ✅已改 | 把 `company/`、`templates/` 加进向量索引（`vector index-all`，全局资产） | 一条命令 / ~30 行 | 实测：补索引 6.7s，pm 从"重造问卷"变成"引用 v1.0 + 发现 24 小时冲突" | 同一任务前后各跑一次，比对是否出现真实文件路径 |
| **2** ✅已改 | 修 `audit_output` 日期正则：排除"分钟/小时/步/项/页"等区间与"第/交付物/共"等计数语境 | ~12 行 | 真实产出 0 误报，不再为噪音支付 auditor 调用 | 拿 `0-5分钟` 单测，应不再报 |
| **3** ✅已改 | `max_tokens` 1500 → 4000；被截断时在文件尾写"⚠ 输出被截断" | ~6 行 | "定稿类"任务不再断在半张表，也不再默默打勾 | 重跑 T-0011，文件应完整到关闭条件 |
| **4** ✅已改 | `ROLE_MISSIONS["pm"].verbs` 补"诊断/报价单/报价/方案/验收/交付物/范围"；launch/go_to_market 两个 bundle 的触发词收窄；"客户/文案"不再被双倍加权 | 约 10 行 | "报价单改一版"从 content+finance 改为 pm；"和客户开会"不再带出 scout | 12 句自然说法复测，8 条进回归测试 |
| **5** ✅已改 | 新增 `facts add / list`：口述事实直接入库，强制来源分级 S1-S4 与日期，按内容哈希去重；`recent_facts` 并入全局事实 | 约 60 行 | `secretary` 从"整表无数据"变成"2 行真实客户 + 1 行明确空"；`pm`/`auditor` 同时受益 | 录 4 条真实 S1 事实后重跑 T-0028 |
| **6** ✅已改 | 检索注入：`k` 5 → 8、片段 160 → 600 字；另给每个命中文件补一行「卡头」（版本/定价原则/硬规则都写在首块，首块排名第 19，k 调大也进不来） | 2 个数字 + ~15 行 | 消除"半懂"：报价单模板进了提示词，模型逐字引用"按结果定价，不按人天"并据此推翻上一轮的误判 | 重跑 T-0011，报价单应被正确引用而非写"未检索到" |
| **7** ✅已改 | 新增 `GET /api/output`（只放行 `agency/outputs/`），任务卡/汇报抽屉/调度记录表/角色抽屉的产出路径全部变成可点链接 | ~14 行 + 前端 4 处 | 派完活直接在页面上点开产出，不用翻目录 | curl 200/403/404 + 浏览器实测 7 个链接 |
| **8** ✅已改 | 产出落盘前扫描 `company/ templates/ clients/ …` 下的文件引用，不存在就在文末追加"⚠ 引用了不存在的文件" | ~18 行 | 拦住"company/名单.md"这类幻觉，创始人不会去开一个不存在的文件 | 回放 4 份历史产出，只命中 scout 那一条 |

**排序理由**：1、2、3 已落地，是"同一份产出立刻变好且不再漏钱"；6 是剩余质量差距的主因（实测证据见 13 报告 §11.5 B），两个数字就能改；4 防错误路由；5 是唯一新增能力（也是 secretary 起死回生的唯一路径）；7、8 是体验与兜底。

## 七、现在不建议做的

- **再加角色**。11 个角色里真正能独立交付的只有 content/auditor 两个，再加只是摊薄。
- **继续加 3D 办公室**。页面已经能正常渲染（TOP 3 那块是真有用的），再美化不解决"产物看不见"的问题。
- **无人值守 / 夜间自动执行**。在 facts=0、索引不全的情况下自动化，等于自动生产垃圾。
- **知识图谱 / 商机库**。等 5 号改动（facts 入口）跑一个月、有真实数据了再说。

## 八、给创始人的日常用法（3 分钟）

1. **早上开工**：`python3 agency.py brief`（0.1s），只看"需处理"那几行。
2. **有一件事想不清怎么拆**：`python3 agency.py plan "目标" --days 5`（7s），看完加 `--apply` 入库。
3. **要写东西**：派 `content`（3.9s，质量最高）。
4. **要审东西**：派 `auditor`（能挑出真问题，要人复核标题结论）。
5. **收工前**：把今天做的决定写一行进记忆：
   `python3 agency.py memory set T-00xx pm --slot decisions --text "..." --source "创始人 11-12"`
6. **不要做**：让 `secretary` 整理你没喂给它的记录；让 `scout` 找真实客户名单；相信任何自称"已对齐/已定稿"的产出而不点开核对。

## 九、总评

| 维度 | 评分 | 说明 |
|---|---|---|
| 数据可信度 | ★★★★★ | 台账/一致性/对账四方一致，0.1s 级 |
| 计划能力 | ★★★★★ | plan 是唯一"人机比"明显占优的功能 |
| 写作能力 | ★★★★☆ | content 可直接用；pm/planner 需人校对 |
| 外部事实能力 | ★☆☆☆☆ | 无联网、无数据入口，产出必带"无数据"或"某厂" |
| 自我校验 | ★★☆☆☆ | auditor 有用，但审计正则误报 + 产出自评无校验 |
| 工程完备度 | ★★★★★ | 193 测试、21 表、四方对账、策略可解释 |

**已改并复测：1 补索引、2 日期正则、3 token 上限、4 意图路由、5 facts 入口、6 检索颗粒度与卡头注入、7 产物回链、8 缺失文件告警——八条全部落地（约 160 行）。**
效果：pm 从"重造模板 + 编造改造理由"变成"引用真实模板 + 逐字引用定价原则 + 判定任务不能关闭"；secretary 从"整表无数据"变成"2 行真实客户 + 1 行明确空"；派完活的产物能在页面上直接点开；编造的文件路径会被标出来。
**补充（11.10/11.11）**：`insufficient_quota` 不是余额问题——实测小请求 200、5k token 连发必 429、等 65s 又恢复，是供应商按 60s 窗口算的 endpoint TPM/RPM 限流被塞进了这个误导性 code。边界已实测并写进 `agency/limits.json`：`sensenova-6.8-flash-lite` 单请求 32k、并发 4、约 60 RPM 是当前唯一稳定的主模型；`deepseek-v4-flash` 冷却后仍一用即 429，已退到最后。程序里加了本地限流桶（超预算排队等窗口）、并发闸门和超长提示词的明确报错。

下一步不在"再加功能"，而在**用一周真实工作喂 facts 和台账**——索引、检索、路由都已经到位，缺的只剩真实数据。
