# 以下为提示词正文

## 1. 你的任务

你是一名资深前端工程师兼像素风游戏 UI 设计师。请产出一个**单文件 HTML** 的「FDE 一人公司办公室」交互 Demo。

它用于向客户和合作伙伴演示：一家只有创始人、其余工作由 AI Agent 承担的公司，如何通过看板调度、工位协作、审计监督和老板办公室来运转。

这不是真实业务系统，是**演示级前端**。所有数据内嵌，所有交互本地模拟。

---

## 2. 背景：这是一家什么公司

### 2.1 FDE 是什么

FDE = Founder-Driven Execution，创始人驱动执行。公司只有创始人一个真人，其余角色由 AI Agent 担任。Agent 不是聊天机器人，而是有明确岗位、明确交付物、明确验收标准的「数字员工」。

### 2.2 公司怎么运转

- 所有工作以**任务**为单位，任务挂在**项目**下。
- 任务有唯一负责人（owner）、截止日、验收条件、关闭证据。
- 任务状态只有 6 种：`todo` 待领取、`doing` 进行中、`blocked` 阻塞、`review` 待验收、`done` 已验收、`closed` 已关闭。
- 工作由**事件**驱动，不靠固定早会。任务创建、临期、逾期、阻塞、里程碑达成，都会触发对应 Agent 行动。
- 公司有一条**宪法**，最高优先级：禁止臆造，所有事实必须标注来源等级。
- 事实来源分四级：S1 客户原话或书面确认；S2 客户文档或系统数据；S3 公开资料；S4 推断假设（必须标注「假设，待核实」）。
- 对外文档没有事实台账，审计可以冻结；没有客户书面确认单，规划师不得排期；没有证据，任务不得关闭。

### 2.3 这家公司现在在做什么

项目代号 OPC-002，内部孵化，目标是建成一套可独立接单的 AI 工作台：能对陌生客户做 30 分钟诊断并出报告，能 2 小时出方案和报价，能管理任务台账，能换一台机器原样运行。计划 2026-11-15 上线。

### 2.4 术语表（Demo 中出现的词，必须按此理解）

| 术语 | 含义 |
|---|---|
| 项目 | 有目标、有范围、有关闭条件的交付单元 |
| 任务 | 项目下可独立执行、有 owner、有截止、可验收的最小工作单元 |
| 看板 | 任务流转的可视化投影，分待领取 / 进行中 / 待验收 / 已完成四列 |
| 工位 | 每个 Agent 的固定座位，代表其岗位归属 |
| 调度 | 把任务从看板分派到具体工位，并跟踪流转 |
| 闸门 | 开工前的强制检查点，七项确认不齐不许写代码 |
| 确认单 | 客户书面确认范围与验收指标的凭证，是排期的唯一前置 |
| 审计 | 独立监督角色，直属创始人，可冻结文档、暂停发布 |
| 事实台账 | 交付物附带的事实来源对照表 |
| 受限资料 | 密钥、密码、证件号等敏感信息，单独存放，默认不外发 |

## 3. Demo 定位与硬边界

### 3.1 一句话

用像素风办公室，把「老板下指令 → CEO 调度 → Agent 干活 → 审计把关 → 老板看经营数据」这条链路演出来。

### 3.2 技术边界（不可突破）

1. **只允许一个 HTML 文件**：`index.html`，CSS 与 JS 全部内联。
2. **禁止任何外部依赖**：不引用 CDN、外部字体、外部图片、图标库、JS 框架、CSS 框架。
3. **禁止任何网络请求**：没有 `fetch`、`XMLHttpRequest`、WebSocket、`<img src="http...">`。
4. **禁止后端**：双击文件即可打开，断网可用。
5. 所有图形用 CSS、内联 SVG 或 Canvas 绘制；人物必须是代码画出来的像素小人。
6. 所有数据内嵌在 JS 常量中，页面顶部常驻「演示数据」标记。
7. 刷新页面后状态重置；如需保留，只允许用 `localStorage` 存「演示进度」和「减少动效」开关，不存业务数据。
8. 不引入真实密钥、真实客户信息、真实手机号、真实邮箱。

### 3.3 「动作虚放」是什么意思

这是本 Demo 最重要的表现规则：

- 人物走动、取卡、交谈、盖章，都是**调度过程的舞台化表达**，不是真实执行顺序。
- 动画不需要与任何后端事件一一对应，不需要证明「谁在什么时候真的做了什么」。
- 允许预先编排剧情、允许加速、允许人物走到看板再走回来。
- 但同一时刻必须自洽：一个人不能同时在两个地方，不能同时做两个动作。
- 每个动作都要有**意图标签**，让观众看懂「他在干什么」，例如「去取卡」「去交接」「去冻结」「去验收」。
- 动作是示意，不是承诺。不要在任何地方写「实时」「真实运行」「正在调用模型」这类字样。

### 3.4 两种模式

| 模式 | 行为 |
|---|---|
| 演示模式（默认） | 自动播放一段约 90 秒的完整剧情，可暂停、可重播、可单步 |
| 手动模式 | 用户自由点击角色、看板、房间、电话，触发对应的单段动画 |

两种模式下页面顶部都显示「演示数据 · 非真实运行」。

## 4. 组织与角色

### 4.1 层级关系

```
                    老板（创始人，唯一决策人）
                    │                    ┊
                    │                    ┊ 审计虚线直报
                    ▼                    ┊
              CEO（调度 Agent）          ┊
                    │                    ┊
     ┌──────────────┼──────────────┐     ┊
     ▼              ▼              ▼     ▼
  幕僚长          产品经理        秘书   审计
  商机侦察        规划师          教练
  内容            HR              财务（预留）
```

**关键区分（不要画错）**：

- **老板**是真人、创始人、唯一决策人，坐老板办公室，不在开放办公区。
- **CEO** 是调度 Agent，坐看板正前方，负责分派、催办、升级，**不是老板**，不决策业务，不签确认单，不改宪法。
- **审计**不受 CEO 管理，虚线直报老板，可以当众冻结 CEO 派出去的任务。
- **财务**是灰色空工位，标注「岗位未定义」，不是在职员工。

### 4.2 老板（创始人）

- 位置：老板办公室。
- 视觉：深色西装、金色领带，比其他角色高 2 像素，站在办公桌后或坐在桌后。
- 职责：定方向、拍板、打电话叫人、看经营数据、签署确认单。
- 台词风格：短、直接、只问结果。
- 示例台词：
  - 「先对齐，再开工。」
  - 「这个数字哪来的？」
  - 「T-0016 为什么还卡着？」
  - 「让审计先看。」

### 4.3 CEO（调度 Agent）

- 位置：开放办公区，看板正前方的独立办公桌，桌上有一块小屏幕显示「调度中」。
- 视觉：金色胸牌、深色马甲、手持任务卡；头顶有调度图标（三个点连成箭头）。
- 职责：从看板取卡、按 owner 分派、跟踪流转、超时催办、冲突升级给幕僚长、把结果回报老板。
- 权限边界：不能创建缺五要素的任务，不能改验收标准，不能绕过审计，不能对外承诺。
- 台词风格：流程化、带编号、像调度员。
- 示例台词：
  - 「T-0011，owner 产品经理，今天到期。」
  - 「这张卡缺验收条件，退回。」
  - 「T-0016 阻塞两天，升级幕僚长。」
  - 「审计已冻结，暂停派发。」

### 4.4 九个已入职 Agent（详细）

每个角色都要有：工位、桌上道具、衣服主色、状态徽章、角色卡、至少 3 条台词。

## 5. 场景与布局

### 5.2 开放办公区

- 地板：深蓝灰，30px 网格线，每 5 格一条稍亮的缝。
- 墙面：顶部 4 格高的深色墙，挂看板。
- 大看板：横向占 6..30 格，高 4 格，四列等宽，列头分别是「待领取 / 进行中 / 待验收 / 已完成」，每列右上角有数量。
- CEO 工位：看板正前方偏左，桌子 4×2 格，桌前有一块地毯，颜色比其他工位深。
- A 排工位：5 个，横向等距，每张桌子 5×3 格，桌上有显示器、键盘、名牌、道具。
- B 排工位：5 个，与 A 排对齐，中间留 3 格走道。
- 预留工位：右侧 3 个，虚线桌，灰显。
- 门：右侧墙，2 格宽，有绿色出口指示灯。
- 公告墙：A 排左侧墙面，贴三张纸：「本周目标」「闸门状态」「审计周报」。点击可展开。

### 5.3 老板办公室

- 地板：深色木地板，比开放区更暗，显得私密。
- 墙面：挂一幅抽象画（用 CSS 画，不用图片）。
- 经营看板：占上部墙面，6 个指标卡 + 1 个趋势图 + 1 个环形完成度。
- 老板桌：右下，桌上有一部老式电话、一支钢笔、一份确认单。
- 老板：站在桌后或坐姿，点击有角色卡。
- 三间内门：档案室、机要室在左上和右上，保密室在左下，门上有标牌和状态灯。

### 5.4 档案室

- 视觉：三排书架，书脊颜色按知识分类；中间一张阅读桌，一盏台灯。
- 墙面标语：「无来源，不入库。」
- 交互：点书架 → 打开知识列表；点台灯 → 切换知识图谱视图。
- 知识列表字段：标题、来源等级（S1-S4 彩色标签）、来源说明、日期、关联任务。
- 知识图谱：节点 = 知识条目 / 项目 / 任务，连线 = 引用关系；S4 节点用虚线边框并标「待核实」。

## 7. 五段演示剧本（虚放编排）

### 第一幕 · 开场巡检（0–15s）

1. 镜头切到老板办公室，电话铃响，老板拿起听筒。

3. 镜头切回开放区，CEO 桌前的调度灯亮起。

5. 规划师起身，走到 CEO 桌前，在排期板上贴一张绿色磁贴。
6. 规划师回工位，工位亮起，显示器代码条加速。
7. 看板上 T-0011 从「待领取」滑到「进行中」。

### 第三幕 · 审计拦截（35–55s）

1. 内容从 A4 起身，走到看板前，提交一张「客户案例」卡。
2. 审计从 A1 起身，走到机要室门口，取出宪法小册。

6. 审计走到 CEO 桌前，递一张冻结单；CEO 暂停派发，看板顶部出现「暂停」条。

### 第四幕 · 逾期升级（55–70s）

1. 看板上 T-0016 变红，脉冲。
2. 秘书走到看板前，摘下卡片。
3. 幕僚长从 B1 起身，走到看板前，接过卡片。
4. 两人对视，幕僚长气泡：「资源不够，砍范围。」

6. 事件流新增一条红色「逾期升级」。

### 第五幕 · 关单与收尾（70–90s）

1. 产品经理把诊断报告放到教练桌上。
2. 教练翻看，盖绿色「验收通过」章。
3. 秘书走到产品经理工位，收走卡片，走到看板前，把卡片放入「已完成」。
4. 卡片飞入，触发一次轻微庆祝：所有在岗小人举手 0.5 秒。
5. 老板办公室经营看板数字滚动：完成率 56% → 57%，token 增加 1,200。
6. 画面渐暗，出现一行字：「把判断留下，把重复交给 Agent。」

**编排规则**

- 每一幕的人物位置必须接续上一幕的结束位置，不能瞬移。
- 走路速度统一 2 格/秒；对话时停下。
- 气泡最多 14 个汉字，超出换行，最多两行。
- 每个动作有意图标签，显示在人物脚下，如「去取卡」「去交接」「去冻结」。
- 减少动效开启时，取消走路，改为人物直接出现在目标位置 + 状态徽章。

## 8. 人物状态机与动画参数

### 8.1 状态

| 状态 | 触发 | 视觉 |
|---|---|---|
| `idle` | 默认 | 呼吸起伏，偶尔翻纸 |
| `walk` | 有目标点 | 4 方向行走，8fps，手脚交替 |
| `work` | 工位亮起 | 面向桌子，手部敲击，显示器加速 |
| `talk` | 气泡出现 | 转身面向对方，头顶气泡 |
| `inspect` | 审计/验收 | 举放大镜或翻册子 |
| `blocked` | 阻塞 | 低头，头顶红色感叹号 |
| `celebrate` | 关单/里程碑 | 举手 0.5 秒 |

### 8.2 参数

- 逻辑帧：8fps。
- 人物尺寸：24 × 36 px。
- 方向：上 / 下 / 左 / 右，各 2 帧。
- 描边：1px 深色，像素硬边，`shape-rendering: crispEdges`。
- 阴影：脚下椭圆，透明度 0.25。
- 移动：沿路径节点折线行走，遇到障碍绕行。
- 气泡：白底黑边，尖角指向人物，最多显示 2.5 秒。
- 意图标签：人物脚下 12px 小字，灰底白字。
- 减少动效：所有走路改为淡入淡出，帧动画停止。

### 8.3 点击热区

- 人物：整个小人 + 椅子范围。
- 工位：桌子 + 显示器。
- 看板卡片：整张卡。
- 房间：门 + 房间标牌。
- 电话：听筒。
- 宪法铜牌：单块。
- 保密室状态灯：单盏。
