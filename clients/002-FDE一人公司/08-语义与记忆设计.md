# 08 语义统一与记忆设计

- 版本：v2
- 更新：2026-11-11
- 变更：工作记忆改为持久化结构；向量记忆提前到 P0；新增规范化清单

---

## 0. 两条硬要求

1. **工作记忆不做字符串拼接**，必须是可持久化、可恢复、可压缩的结构化上下文。
2. **向量记忆 P0 就做**，用可替换的最小实现，避免上线后重建。

代价：工期增加约 10 小时，从 16 小时缓冲里出。P0 范围不变。

---

## 1. 语义统一

| 项 | 做法 |
|---|---|
| 术语 | `agents/ontology.md`，每词一句定义 + 一个反例 |
| 枚举 | 状态 `todo/doing/blocked/review/done/closed`；来源 `S1-S4`；授权 `A0-A3`；密级 `L1-L4` |
| 编号 | 项目 `OPC-001`、任务 `T-0001`、事实 `F-0001`、事件 `E-<type>-<id>` |
| 校验 | 写入前校验枚举，非法值拒绝，不静默修正 |
| 一致性测试 | 同一问题问三个角色，判断必须一致 |

## 2. 工作记忆（结构化）

**定义**：一个任务在某角色手中的上下文快照，落库，不依赖进程内存。

```
wm_session
  id, task_id, role, turn,
  goal            目标（一句话）
  constraints     约束（数组）
  decisions       已定决策（数组，带时间）
  open_questions  未决问题（数组，带责任人）
  artifacts       本轮产物引用（路径 + 摘要）
  digest          历史压缩摘要
  token_used, compacted_from, updated_at
```

**组装顺序（固定）**：
1. 目标与约束（必带，不压缩）
2. 未决问题（必带）
3. 最近两轮产物摘要
4. 历史 digest（压缩后）
5. 相关事实与案例（检索注入，≤8 条）

**预算**：8k tokens。超限先压 digest，再减产物，目标与未决问题永不裁剪。

**压缩规则**：每 5 轮或超预算时，把前 5 轮压成 200 字 digest，保留决策与结论，丢弃过程。

**生命周期**：任务创建时建 session → 每轮更新 → 任务关闭转成案例记忆 → session 归档。

**恢复**：进程重启后按 `task_id + role` 读最新 session 续跑，不丢上下文。

## 3. 向量记忆（P0 最小实现）

```
embeddings
  id, project_id, source_type(fact/doc/case), source_id, source_version,
  chunk_no, text, content_hash, model, dim, vector BLOB, state, created_at
```

**切块规范**：512 字，重叠 64 字，按段落边界切，标题并入首块。

**嵌入模型注册表**（已实测）：

| 字段 | 值 |
|---|---|
| model | `bge-m3` |
| dim | `1024` |
| normalize | `true`（输出已 L2 归一化，cos = 点积） |
| 来源 | 本机 Ollama 0.32.5，`/api/embed` |
| 状态 | `active`，P0 默认 |

实测（2026-11-11，中文短句余弦）：

```
0.6079  秘书负责日程提醒和任务催办 | 提醒我明天下午三点关闭任务
0.4077  秘书负责日程提醒和任务催办 | 这家餐厅的川菜很好吃
0.7334  客户要求数据不能出内网   | 禁止把敏感数据上传到外部服务器
0.4233  客户要求数据不能出内网   | 明天上海有小雨
```

相关对明显高于无关对，区分度可用；阈值 0.3 沿用，上线后按真实语料再调。

**向量来源（按优先级）**：
1. 本地 Ollama `bge-m3`（已验证），零成本、不出网 → **P0 采用**
2. 商汤嵌入接口（模型名未验证，不写死）
3. 兜底：纯 Python 的 hash-tfidf 向量，保证链路可跑，语义能力弱

**检索**：余弦相似度暴力计算，`project_id` 过滤，`top_k=8`，阈值 0.3。2 万条以内可接受，实测后再定阈值。

**去重与更新**：`content_hash` 去重；`source_version` 变化触发重嵌，旧向量标 `stale` 不删除。

**抽象接口** `vectors` 模块：`index_path / search / delete_by_source`。P1 换 Chroma 或 pgvector 只改实现。

## 4. 规范化清单（防开倒车）

| 项 | 规范 |
|---|---|
| 结构版本 | `schema_version` 表 + 迁移脚本，禁止手改表结构 |
| 时间 | 统一 ISO8601 UTC，展示层转本地时区 |
| 枚举 | 集中定义一处，代码与文档同源 |
| ID | 前缀 + 定长序号，不复用 |
| 内容指纹 | 所有文本入库带 `content_hash`（SHA-256 前 16 位） |
| 嵌入模型 | 注册表记录 `model/dim/normalize`，换模型必须重嵌并记录 |
| 导出 | JSONL，字段顺序固定，可直接导入另一台机器 |

---

## 5. 写入策略

**必记**：客户原话与书面确认、决策及理由（含被否选项）、失败与踩坑、指标基线、承诺的时间与价格。

**不记**：寒暄、中间推理、可再生成的草稿、重复内容。

**规则**：
1. 一条事实一个来源，无来源不入库
2. 新事实覆盖旧事实，旧的标 `superseded`，不删除
3. 事实带有效期，过期标"待核实"
4. 写入前按 `content_hash` 查重
5. L3/L4 只存索引，正文在受限节点

## 6. 工具选择

| 能力 | P0 | P1 |
|---|---|---|
| 工作记忆 | SQLite `wm_session` | 同左 |
| 事实记忆 | SQLite `facts` | 同左 |
| 全文检索 | SQLite FTS5 | 同左 |
| 向量检索 | 自建 `embeddings` + 暴力余弦 | Chroma / pgvector |
| 嵌入 | Ollama 本地，兜底 hash-tfidf | 商汤嵌入 |
| trace | `agent_runs` 表 | Langfuse |

不引入 Mem0、Zep、LlamaIndex：记忆结构必须自己掌控，否则换模型、换库都要被牵着走。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 上下文污染 | 固定组装顺序 + 预算 + 压缩 |
| 向量质量差 | 先保证可检索，阈值实测；不达标就只用于候选召回 |
| 换模型导致向量失效 | 模型注册表 + `stale` 标记 + 重嵌脚本 |
| 工期挤压 | 预留 8 小时缓冲，先保流程再保效果 |
