# 方案对比｜FDE 一人公司（内部孵化）

- 项目代号：OPC-002
- 日期：2026-11-11
- 前提：单人、1,000 元、6 天（11-12 至 11-17）、无数据
- 说明：以下工作量与成本为估算（S4），不是承诺
- 排期说明：本文件为 2026-11-11 的方案比选记录；最终排期以《03 方案确认单》变更记录为准（已压缩至 11-15 上线）

---

## 1. 三个方案

| | A 交付系统 v0.5 | B 交付系统 + 可演示 demo | C 仅获客包 |
|---|---|---|---|
| 核心交付 | 诊断包、报价单、项目模板、任务台账、定位卡、话术 | A 全部 + 一个可现场演示的知识库问答 demo | 定位卡、20 人名单、话术、3 篇内容 |
| 6 天可行性 | 高 | 低（需 8-10 天） | 高 |
| 成本估算 | 0-300 元 | 300-800 元 | 0 元 |
| 能接什么单 | 诊断单、小型项目（外援配合） | 诊断单、可现场演示的试点 | 只能接诊断单 |
| 主要风险 | 无案例，成交靠信任 | 工期挤压，demo 效果受限 | 不能支撑"独立交付" |
| 数据依赖 | 无 | 需公开数据，不能编造 | 无 |

---

## 2. 方案 A：交付系统 v0.5（推荐）

**交付物**

1. 诊断包：问卷、30 分钟访谈提纲、诊断报告模板、报价单。
2. 项目模板：需求 → 方案 → 确认单 → WBS → 验收，一套可复用。
3. 任务台账 + 事件检查脚本：到期、临期、逾期能自动报出。
4. 定位卡：一句话定位 + 3 个候选场景。
5. 对外话术：开场、报价、拒绝、异议处理。
6. Agent 执行手册：9 个角色怎么调用、输出什么格式。

**6 天排布（草案，待规划师细化）**

| 日期 | 交付 |
|---|---|
| 11-12 | 诊断包定稿 + 报价单 |
| 11-13 | 项目模板 + 任务台账 + 检查脚本 |
| 11-14 | 定位卡 + 服务一页纸 + 话术 |
| 11-15 | 场景卡 + demo 脚本（不开发） |
| 11-16 | 全流程彩排：模拟诊断 → 方案 → 报价 |
| 11-17 | 验收 + 审计 + 上线 |

**验收标准**

- 陌生客户 30 分钟内完成诊断并出报告。
- 2 小时内出一页方案 + 报价。
- 任务台账能准确报出到期与逾期。

---

## 3. 方案 B：A + 可演示 demo

**增量**：用公开数据做一个知识库问答 demo，可现场演示检索、回答、引用来源。

**代价**：
- 需要额外 2-3 天，6 天内完成会挤压验收。
- 成本增加 300-800 元（embedding、API、向量库）。
- 公开数据的效果不代表客户场景，演示时容易过度承诺。

**建议**：放到第一单之后，按客户真实数据做，避免现在猜错方向。

---

## 4. 方案 C：仅获客包

**交付**：定位卡、20 人名单与打分、开场话术、3 篇内容初稿。

**适合**：只想先验证有没有人愿意付诊断费。

**不适合**：目标是"能独立交付"，C 不解决交付能力。

---

## 5. 推荐

**选 A。** 理由：

1. 11-17 要接单，最先需要的是"能诊断、能报价、能排期"，不是 demo。
2. 没有客户数据时做 demo，等于替客户猜场景，命中率低，还容易过度承诺。
3. demo 可以在第一单里用客户真实数据做，既省成本，又能沉淀案例。
4. 1,000 元预算下，A 的成本几乎为零，留出余量应对意外。
