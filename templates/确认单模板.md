## 1. 七项开工条件

| # | 项 | 确认内容 | 空缺时 |
|---|---|---|---|
| 1 | 目标 |  | 阻塞 |
| 2 | 范围（做什么） |  | 阻塞 |
| 3 | 验收标准 |  | 阻塞 |
| 4 | 不做什么 |  | 阻塞 |
| 5 | 技术边界 |  | 阻塞 |
| 6 | 时间与工时 |  | 阻塞 |
| 7 | 确认人 | 姓名 + 日期 + 确认方式 | 阻塞 |

> 填写提示：
> - 第 3 项必须是可判定的句子，出现"好用""稳定"要补量化口径。
> - 第 4 项写"不做 X"，不写"暂不考虑 X"。
> - 第 5 项写清允许用什么、不允许用什么，以及数据能不能出内网。
> - 第 6 项写起止日期、每日投入、计划工时与缓冲；缓冲低于 20% 要标注超载。
> - 第 7 项没有日期或没有确认方式，视为未确认。

## 6. 变更规则

- 范围变更：先撤销闸门（`gate revoke`），评估影响，再重新确认；未重新确认不开工。
- 口头调整不算变更，必须回写本单第 7 节。
- 变更导致工时增加超过 10%，同步更新 WBS 与报价。

## 8. 提交前校验（自动拒绝规则）

- [ ] 七项全部有内容，无空白单元格
- [ ] 验收标准 ≥3 条且可判定
- [ ] 不做什么 ≥3 条
- [ ] 时间含起止日期与缓冲
- [ ] 确认人有姓名、日期、确认方式
- [ ] 预算上限明确

**任一项未勾选：状态保持"未确认"，不得排期、不得建 code 类任务。**
