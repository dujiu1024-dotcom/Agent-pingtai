# P-UI-003 Round 3 原型布局基线（L3-T01）

> 本文档是 Round 3 总控的原型阅读与实现对齐基线。唯一视觉事实来源：`frontend/prototypes/agent-platform.html`。原型为 1536 × 1024 桌面画布；本文件只记录 home 与 office 主视图的结构、布局和行为，不复制原型演示数据作为生产数据。

## 1. 全局画布与视觉系统

- 设计画布：1536 × 1024；页面以画布为基准等比缩放并居中，保持坐标关系。
- 背景：`#aebbd8`；主文字 `#1c2540`；辅助文字 `#6b7794`；主色 `#2f6af0`。
- 字体：系统无衬线优先，中文依次回退 PingFang SC / Noto Sans SC / Microsoft YaHei。
- 面板：半透明白色、约 16px 圆角、柔和蓝灰投影和背景模糊；导航激活态为蓝色渐变。
- 全局结构：左侧固定导航、顶部搜索与全局操作区、右侧主内容画布。
- 交互原则：键盘焦点可见；动效尊重 prefers-reduced-motion；桌面比例缩放不改变设计画布内部尺寸。

### 2.2 KPI

四张卡片分别表达任务运行量、累计成本、成功率、平均耗时。图标、颜色和趋势方向用于快速区分指标；数值必须来自真实统计接口。原型中的数字仅为演示样例，不可在免登录/无数据模式伪装成真实指标。无统计数据时显示占位符或明确空态，并说明数据尚未接入。

### 2.3 趋势图

系统概览展示任务数与成功率两条趋势序列，包含图例、纵轴刻度、时间刻度和状态摘要。实现时应区分双指标量纲，避免把成功率误读为任务数量；无数据时保留图表容器、标题和图例，并展示可理解的空态。

### 2.4 任务列表

任务面板包含全部任务、运行中、等待审批等筛选入口；每行至少体现任务名称、状态、进度/提交时间、必要的辅助说明。运行中任务显示进度；等待审批显示醒目状态；完成态显示耗时或完成信息。列表为空时使用空态，不使用静态演示任务冒充真实记录。

### 2.5 热门 Agent 与动态 Feed

热门 Agent 至少体现排名、名称/角色、相对使用量和数值；动态 Feed 至少体现时间、事件类型和摘要。两者在同一底部信息带并列，卡片高度、标题基线、内边距和行距保持一致。无记录时分别展示模块级空态。

### 2.6 快捷入口与导航

主视图热区覆盖 Agent 助手/创建入口、运行任务、Workflow 管理及任务面板入口。左侧导航顺序为工作台、3D 办公室、任务中心、Agent 协作、Workflow、成本分摊、系统管理，并提供折叠操作。顶部提供全局搜索、通知和主题操作。React 实现应使用现有路由，不另造平行导航或复制业务页面。

## 3. Office 3D 办公室主视图

### 3.1 页面骨架

- Office 是独立主视图（原型标识 `data-v="office"`），由左侧全局导航与顶部全局操作区共享应用壳。
- 主面板位于 x=205、y=90，尺寸约 1306×890，白色半透明圆角卡片。
- 面板标题为“3D 办公室”，标题旁显示在线 Agent 数及悬停提示。
- 场景视口约 x=258、y=152，尺寸 1200×805；场景内容包含办公室空间底图、人物/Agent Sprite、地面阴影和悬停提示层。
- 场景主体使用沉浸式空间透视；人物状态通过位置、轻微呼吸/摆动动画及悬停信息表达。

### 3.2 场景交互与状态

- Agent Sprite 至少区分静态工位与巡检/移动角色；悬停显示 Agent 名称、当前任务和状态。
- 运行状态不能只靠颜色表达，需提供文字/辅助说明。
- 场景缩放与窗口变化必须保持视口边界和人物定位一致；减少动态效果时遵循系统减少动态偏好。
- 当前后端若未提供真实楼层、工位坐标、移动轨迹或事件流，不得虚构实时定位。应明确标识示意布局/未分配工位，状态仅使用真实 API 可证实的数据。
- API 加载失败、无 Agent、无运行记录均需有独立加载/错误/空态，不把错误解释成“全部空闲”。

### 3.3 原型技术语义边界

原型的空间底图及人物资源以内嵌图片/Sprite 方式呈现，并由脚本驱动人物微动和沿车道移动；它不是 Three.js/WebGL 场景。视觉对齐验收应优先复刻原型的空间构图、透视、背景、人物密度、阴影、悬停提示与交互，不应把“使用 3D 引擎”误当成原型的必要条件。若采用真实 3D 引擎，最终画面仍须与原型视觉一致，且不能牺牲真实状态语义。
