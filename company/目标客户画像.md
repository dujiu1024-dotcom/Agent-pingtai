# 目标客户画像｜AI 原生运行底座

- 版本：v0.2
- 更新：2026-11-21
- 状态：定位转向渠道合作，客户从"终端企业"变为"软件公司（渠道方）"；下方事实/判断需按新定位重新验证

---

## 1. 客户是谁

我们的直接客户是**软件公司（渠道方）**，不是终端企业。终端企业由软件公司去触达和交付。

| 类型 | 特征 | 痛点 | 优先级 |
|---|---|---|---|
| 行业软件公司 | 已有行业客户，卖 SaaS / 定制软件 | 想加 AI 产品线，但没 AI 底座能力 | 高 |
| 系统集成商 | 有大客户关系与交付团队 | 客户要 AI，自己只能堆人力做，无法复制 | 高 |
| AI 应用服务商 | 做过几个 AI 项目 | 每个项目重来一遍，缺标准底座 | 中 |
| 有行业资源的创业团队 | 懂行业、有客户，不写代码 | 想做 AI 产品但缺技术底座 | 中 |
| 大型企业 IT | 自建为主 | 倾向自研，采购流程长 | 低，暂不碰 |

**一句话画像**：有行业客户、懂行业场景，但缺一套能跑生产的 AI 底座的软件公司。[假设·S4 待验证]

---

## 2. 他们的痛点

1. **自研底座太贵**：多租户、权限、审计、工具安全、配额、可观测——做齐要 6–12 人月，还要持续维护。
2. **底座不是差异化**：行业 Agent 才是他们的护城河，但没底座 Agent 跑不到生产。
3. **demo 到生产的鸿沟**：开源框架能跑 demo，但没多租户、没审批、没灰度迁移，过不了企业安全评审。
4. **交付不可复制**：每个客户项目重来一遍，无法规模化。

---

## 3. 我们卖的是什么

不是卖开源框架，是卖**企业级就绪的运行底座 + 长期升级支持**：

| 形态 | 内容 | 适合谁 |
|---|---|---|
| 底座授权 | 私有部署 / 专有云 / SaaS 多租户 | 有交付能力的软件公司 |
| 底座 + 代装 | 帮装好、配好首个租户与 Extension | 首次合作的渠道 |
| 底座 + 共建 | 一起把首个行业 Agent 做成 Extension | 战略种子伙伴 |

---

## 4. 他们怎么赚钱（说服点）

- 装上底座 + 加行业 Agent = 一个可交付的新产品线。
- 一个行业 Extension 包复制到多个客户，边际成本递减。
- 收解决方案的钱（项目制 + 续费），我们只收底座授权费。
- 底座持续升级、安全补丁由我们负责，他们专注行业 Agent。

## 5. 渠道打法（待验证）

| 渠道 | 内容形态 | 作用 |
|---|---|---|
| 定向触达 | 找有行业客户的软件公司老板，1 对 1 演示底座 | 高质量线索 |
| 行业社区 / 生态 | 模型厂商生态、集成商分包、开发者社区 | 中期起量 |
| 案例内容 | 第一个渠道伙伴的成功案例拆解 | 建立信任 |

**硬前提**：必须先有一个跑通的种子案例。先服务好 1 个渠道伙伴做出可公开案例，再复制。

---

## 6. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 软件公司付费意愿未知 | 习惯开源免费 | 强调企业级就绪与省下的人月成本 |
| 需要可演示底座 | 必须能现场装、现场跑 | 准备一键部署 + 控制台演示 |
| 渠道交付能力参差 | 装不好会砸口碑 | 提供"底座 + 代装/教学"，先把第一个带跑通 |
| 定位漂移 | 被当成外包 | 明确：我们卖底座，行业 Agent 和客户归渠道 |
