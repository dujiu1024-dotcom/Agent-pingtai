# S-665-01 — Agent → Workflow → Run → Blackboard → notification E2E

## Scope

This suite covers the deterministic, service-level end-to-end journey required by Issue #665:

1. Create and publish a tenant-scoped Agent through `RegistryService`, then resolve its active version.
2. Create and start a platform Run lifecycle record.
3. Compile and execute the multi-expert LangGraph workflow.
4. Persist expert claims, synthesis, and the accepted final artifact through `BlackboardMultiExpertServices`.
5. Finish the Run as succeeded and relay a completion notification through `OutboxRelay`.
6. Assert the notification payload references the exact persisted Run, task, and final Blackboard artifact.

## Automated test

Run:

```bash
python -m unittest tests.test_issue_665_s_665_01_e2e -v
ruff check tests/test_issue_665_s_665_01_e2e.py
```

The test uses in-memory registry, Run state, Blackboard, outbox, audit, and notification transport adapters. LangGraph's in-memory checkpointer is used for deterministic workflow execution.

## Evidence boundary

This is an automated integration/E2E contract test, not a production deployment test. The notification transport and outbox store are test doubles; no live Redis, PostgreSQL, Vault, model provider, webhook, or external notification service is contacted. Production persistence, delivery provider acceptance, and browser/device notification receipt remain outside this task and are not claimed as verified.

The new test is included in the repository Ruff allowlist. GitHub Actions is the authoritative CI result; local execution is not claimed unless independently run in a repository checkout.
