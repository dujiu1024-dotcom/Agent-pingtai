# 平台端到端、安全回归与发布门禁

## 新增自动化门禁

`.github/workflows/platform-release-gate.yml` 在 Pull Request 和手动触发时执行：
- PostgreSQL 16 + pgvector、Redis 7.4 服务容器健康检查。
- 身份登录、知识文档写入、RAG 引用回答、跨租户不可见的端到端测试。
- 身份 HTTP/CSRF、安全授权、知识权限、多专家审批、Tool Gateway、OCI 沙箱、Run 生命周期、Outbox、PG/Redis 集成测试。
- 固定 10,000 次策略评估的宽松性能 smoke ceiling（5 秒）；该值只作为粗粒度回归哨兵，不等价于容量压测。
- Ruff 与 mypy 静态检查。

## 安全负向回归

新增端到端测试确认：
- Prompt Injection 文本不能通过参数字段伪造审批授权。
- 高风险动作没有审批 ID 必须拒绝。
- 审批摘要绑定动作资源与参数；目标变化后旧摘要失效。
- 敏感字段在观测载荷中脱敏。
- OCI Sandbox 命令包含 network=none、只读根文件系统，且不启用 privileged。

已有安全测试继续覆盖未知工具拒绝、角色不足、资源授权失败、审计写入失败关闭、幂等键重放和 L3 人工执行边界。

## 发布流程

Release Gate 必须全部通过才允许进入人工发布评审。生产发布仍需检查迁移、备份、回滚、依赖供应链、密钥轮换和运行指标。失败时禁止发布；修复后重新运行完整门禁。

## 验收边界

本 PR 提供可重复的自动化门禁和关键链路样例，不替代真实生产负载、跨实例故障注入、沙箱逃逸红队、灾备恢复和生产用户验收。部署、真机、演练类验证按要求跳过，统一标注「待用户真机验证」。
