# 本地与单机基础设施部署基线

本 Compose 文件启动平台所需的 PostgreSQL/pgvector、Redis 和 S3 兼容对象存储 MinIO。它是**基础设施层**，不是完整应用部署：当前平台应用需要宿主提供身份、知识库、运行时、授权器及 Worker 的组合装配，不能用一个未经配置的 API 容器冒充生产就绪。

## 启动

```bash
cp deploy/.env.example deploy/.env
# 编辑 deploy/.env，为所有 REPLACE_* 项生成独立随机密码
docker compose --env-file deploy/.env -f deploy/compose.yaml config
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
```

Compose 变量缺失时会拒绝启动。数据库、Redis 和 MinIO 的宿主端口默认仅绑定 127.0.0.1；远程访问应通过受控私网/反向代理，不要直接暴露管理端口。

## 连接参数

| 服务 | 容器内地址 | 默认宿主地址 | 持久化卷 |
|---|---|---|---|
| PostgreSQL + pgvector | postgres:5432 | 127.0.0.1:5432 | postgres_data |
| Redis（AOF + 密码） | redis:6379 | 127.0.0.1:6379 | redis_data |
| MinIO S3 API | minio:9000 | 127.0.0.1:9000 | object_data |
| MinIO Console | minio:9001 | 127.0.0.1:9001 | object_data |

容器间连接使用服务名；宿主进程连接使用 127.0.0.1。Redis 客户端必须配置 `REDIS_PASSWORD`。应用启动前应等待三个服务健康，不要只依赖容器进程已启动。

## 生产化约束

- 将 `deploy/.env` 替换为 Vault/KMS 或编排平台 Secret 注入；禁止提交真实凭据。
- 生产环境应将 PostgreSQL、Redis、对象存储放在私有网络，启用 TLS/传输加密、最小权限账号、资源限制和监控。
- 命名卷只提供本机持久化，不等同备份；按《PostgreSQL备份恢复与发布运行手册》执行加密备份，并为对象存储配置独立版本化/异地备份。
- PostgreSQL 是业务事实源；Redis 可重建，不能保存唯一业务事实。Outbox 消费恢复仍需执行对应演练。
- 升级前备份；迁移采用 expand/contract。破坏性迁移不能仅靠回滚应用镜像恢复。
- `docker compose down` 保留命名卷；`docker compose down -v` 会删除本地数据，仅可在确认后用于销毁开发环境。

## 验收边界

CI 仅静态校验 Compose 结构和环境变量/端口/健康检查契约。空环境真实启动、跨重启持久化、备份恢复、对象存储异地恢复、升级回滚和 RPO/RTO 实测仍需目标环境演练，不在此处虚报通过。
