# 平台备份恢复与灾备演练清单

> 本文是操作前检查和隔离环境演练手册，不是生产执行授权。所有恢复演练必须使用隔离目标、经授权的备份副本和合成/脱敏数据。

## 1. 现有能力与限制

| 数据域 | 现有脚本 | 备份形式 | 恢复保护 | 已知限制 |
|---|---|---|---|---|
| PostgreSQL | `scripts/backup_postgres.sh` / `scripts/restore_postgres.sh` | pg_dump custom + age 加密 + SHA-256 + manifest | 显式确认、校验密文与 manifest、解密后 `pg_restore --list`、单事务恢复 | 恢复会覆盖目标库同名对象；必须使用隔离目标验证 |
| Redis | `scripts/backup_redis.sh` / `scripts/restore_redis.sh` | RDB 快照 + age 加密 + SHA-256 + manifest | 显式确认 Redis 已停止、校验 RDB、保留恢复前 RDB | RDB 是时间点快照，不是 AOF 历史归档；恢复需停机 |
| MinIO | `scripts/backup_object_storage.sh` / `scripts/restore_object_storage.sh` | `mc mirror` + tar.gz + age 加密 + SHA-256 + manifest | 显式确认、校验 bucket/manifest、拒绝路径穿越和链接条目 | mirror 仅保存当前对象状态，不保留历史 object versions；默认不删除目标多余对象 |

现有 `scripts/deploy_infrastructure.sh` 与 `scripts/rollback_infrastructure.sh` 回滚的是 Compose 环境配置/基础设施服务，不是数据库 schema 或业务数据回滚。

PostgreSQL 迁移由 `scripts/migrate_postgres.sh` 执行，使用 advisory lock 和 migration checksum；检测到已应用迁移内容变化会拒绝继续。该机制不自动生成逆向 SQL。

## 2. 演练准入条件

- [ ] 负责人、变更窗口、通知对象和停止条件已确认。
- [ ] 目标是独立隔离环境，网络策略阻止访问生产数据库、生产 Redis 和生产对象存储。
- [ ] 使用专门的恢复凭据与 age identity；密钥不写入仓库、命令行参数、日志或演练报告。
- [ ] 备份文件、`.sha256` 和 `.manifest.json` 三件套齐全，且来源、时间、加密身份可追溯。
- [ ] 已记录恢复目标初始状态并完成快照；确认恢复不会覆盖生产数据。
- [ ] 演练数据为合成或脱敏数据，严禁导入真实用户数据到未批准环境。

任一条件未满足即停止，不执行恢复。

## 3. PostgreSQL 恢复演练

参考：`docs/operations/PostgreSQL备份恢复与发布运行手册.md`。

1. 在隔离 PostgreSQL 实例创建空恢复数据库，确认连接串只指向该实例。
2. 设置 `PG_DSN`、`AGE_IDENTITY`、`BACKUP_FILE` 和 `CONFIRM_RESTORE=RESTORE-PLATFORM-DATABASE`。
3. 执行 `bash scripts/restore_postgres.sh`；脚本应先验证 checksum、manifest、数据库名和归档目录，再执行单事务恢复。
4. 记录备份时间、恢复开始/结束时间、目标数据库、脚本退出码和恢复日志摘要。
5. 检查 schema migration ledger、关键表行数、租户隔离、用户/Run/Task 关联、对象元数据、Outbox 未投递事件。
6. 执行应用只读健康检查和抽样查询；不连接生产流量，不进行切换。
7. 保存演练证据并销毁临时恢复实例及临时密钥副本。

## 4. Redis 恢复演练

1. 在隔离 Redis 实例及独立数据目录中进行；不得复用生产 volume。
2. 记录 Redis 停止前数据量、AOF/RDB 配置和最后成功快照时间。
3. 设置 `AGE_IDENTITY`、`BACKUP_FILE`、`REDIS_DATA_DIR`、`REDIS_STOPPED_CONFIRM=YES` 和 `CONFIRM_REDIS_RESTORE=RESTORE-PLATFORM-REDIS`。
4. 执行 `bash scripts/restore_redis.sh`；确认 `redis-check-rdb` 成功且旧 RDB 被保留为 `.pre-restore.*`。
5. 按隔离环境的 Redis UID/GID、文件权限和配置启动 Redis，检查 key 数量、TTL、ACL 和应用连通性。
6. 注入 Redis 暂时不可用场景，验证 PostgreSQL Outbox 可重放及消费者 event_id 去重；Redis 不得成为唯一业务事实源。
7. 记录恢复时长、丢失窗口、Outbox 重放数量和最终一致性结果。

## 5. MinIO 恢复演练

1. 选择隔离 bucket，确认 bucket 名与备份 manifest 完全一致。
2. 设置 `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`、`AGE_IDENTITY`、`BACKUP_FILE` 和 `CONFIRM_OBJECT_RESTORE=RESTORE-PLATFORM-OBJECTS`。
3. 默认执行恢复，不设置 `OBJECT_RESTORE_DELETE_EXTRA=1`；禁止在首次演练启用删除目标多余对象。
4. 执行 `bash scripts/restore_object_storage.sh`，验证 checksum、manifest、解密归档和路径安全检查。
5. 对比对象数量、对象大小、抽样内容 hash、Content-Type/metadata 和应用引用。
6. 只有在单独批准的隔离测试中才演练删除多余对象分支；不得在生产 bucket 演练。
7. 明确记录：当前 mirror 备份不包含历史版本、对象锁/保留策略状态或跨站复制状态，需另行设计和验收。

## 6. RPO/RTO 记录

以下为建议的演练目标，不是已承诺 SLA，也不是当前实测值。最终目标需由业务负责人批准。

| 数据域 | 建议 RPO 目标 | 建议 RTO 目标 | 实测值 |
|---|---:|---:|---|
| PostgreSQL | ≤ 15 分钟 | ≤ 60 分钟 | 待隔离演练 |
| Redis | ≤ 5 分钟（结合 RDB/AOF 策略） | ≤ 30 分钟 | 待隔离演练 |
| MinIO | ≤ 24 小时 | ≤ 120 分钟 | 待隔离演练 |

RPO = 故障时刻与可恢复数据最新时间点的差值。RTO = 故障确认到服务和关键业务校验恢复的总时长。报告必须注明备份频率、备份完成时间、恢复点、开始/结束时间、数据抽样结果和未恢复的数据域。

## 8. 禁止事项

- 不在生产环境首次验证恢复脚本。
- 不在未取得明确授权时执行生产恢复、数据覆盖、灾备切换或 DNS/流量切换。
- 不把 Compose 配置回滚描述为 schema 或数据回滚。
- 不把脚本退出码为 0、静态测试通过或 CI 通过描述为备份可恢复。
- 未完成实际演练前，不填写实际 RPO/RTO，不关闭 #18。
