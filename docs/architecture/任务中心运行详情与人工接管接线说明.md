# 任务中心、运行详情与人工接管接线说明

关联：Issue #9

## 任务中心

- `PostgresTaskCenterService` 实现 Workbench 的 TaskCenterService 契约：任务创建、幂等提交、列表/详情、取消、队列领取、Run 绑定和结果回写。
- `idempotency_key` 按 tenant + actor 唯一；同一键但 Agent、项目、会话、输入或优先级不同会拒绝，不会静默复用旧任务。
- 队列按 priority DESC、available_at、created_at 排序；使用 `FOR UPDATE SKIP LOCKED` 并发领取、Worker 租约心跳、过期接管、指数退避和最大尝试次数。
- `TaskQueueWorker` 的 execute_task 回调必须复用平台已有的 Run 创建、注册快照、LangGraphRunExecutor、Gateway 和配额机制；不得绕过现有执行安全边界。

## Run 详情与事件

- `PostgresRunDetailService` 返回 Run 的输入/输出、Agent、模型模板版本、工作流、用量、trace、时间、Checkpoint 和错误摘要。
- `PostgresRunStateStore.transition` 在同一事务内写入 `platform_run_events` 状态变化事件。
- `RunInterventionService.list_events` 提供时间线；人工提交和应用上下文也写入事件。

## 人工暂停、补充上下文与接管

1. Worker 通过 `LangGraphRunExecutor.pause` 获取真实 LangGraph Checkpoint；没有持久化 Checkpoint 时拒绝暂停。
2. 暂停会持久化 PAUSED 状态和 Checkpoint，并取消当前图任务/工具调用；Executor 不会把主动暂停误判为崩溃中断。
3. 具有 `pause` / `intervene` 权限的操作者可提交 context、decision 或 takeover 类型干预。仅 PAUSED Run 接受人工干预。
4. `POST /runs/{run_id}/resume` 将 PAUSED 转成可恢复的 INTERRUPTED 状态；没有 Checkpoint 时拒绝。
5. 恢复 Executor 必须注入同租户的 `RunInterventionService` 和 `intervention_applier`。在恢复图之前，服务按行锁顺序读取 pending intervention，调用宿主 applier 将其写入 LangGraph 持久化状态，再将干预标记 applied 并记事件。
6. 若 applier 失败，数据库事务回滚，干预仍保持 pending，Run 恢复失败关闭，不会悄悄丢弃人工输入。

## 生产装配

- `create_platform_app` 可注入 `task_service_resolver`、`run_intervention_resolver`、`run_detail_resolver` 和 `run_executor_resolver`。
- Workbench TaskCenter resolver 应返回租户绑定的 `PostgresTaskCenterService`。
- Run API 的 intervention/detail resolver 应返回同租户 `RunInterventionService` / `PostgresRunDetailService`。
- LangGraph Executor 的 intervention store 与 API 使用同一租户的干预仓储；applier 需按 intervention_id 幂等更新 Checkpoint 状态。
- 新增 migration `028_task_center_interventions.sql`；部署时应用所有 migrations。

真实多 Worker 崩溃/恢复、外部工具副作用对账与补偿、模型/工具执行结果、生产图状态 Schema 和人工接管权限策略仍需在目标部署环境验证。
