# 控制面注册、会话、文件与连接器实现说明

## 1. 范围

本说明记录 #7 Agent/模型/工具/Skills 注册管理，以及 #8 会话、文件资产和外部数据连接器的当前实现边界。旧 console/gui 和旧 conversation/docs 数据仍保留，不作为新平台唯一事实源。

## 2. 注册中心（#7）

代码：
- `agent_platform/control_plane/registry.py`
- `agent_platform/control_plane/postgres.py`：`PostgresRegistryRepository`
- `agent_platform/api/registry.py`
- `agent_platform/runtime/registry_snapshot.py`
- `agent_platform/runtime/postgres_registry_snapshot.py`

能力：
- Agent、Workflow、Tool、Skill、Model Provider、Model Template 使用统一租户版本仓储。
- 草稿、发布、回滚均创建新版本；历史版本不可变。
- 发布版本更新 active pointer；停用先移除 active pointer，再写入 disabled 版本，失败时优先保证不再被解析为 active。
- 版本写入采用 PostgreSQL advisory transaction lock + expected latest version。
- 定义中拒绝常见明文凭据字段；只允许保存 secret reference。
- 管理 API 的 Principal、租户仓储和资源授权器由宿主注入。

运行快照：
- 调度方在 Run 执行前调用 `RunRegistrySnapshotService.pin(tenant_id, run_id, references)`。
- 快照记录每个 kind/item_id 的发布版本、定义和 SHA-256 digest。
- PostgreSQL 将快照一次性写入 `platform_runs.registry_snapshot`；后续不同 digest 的覆盖被拒绝。
- `LangGraphRunExecutor` 注入快照内容和 digest 到 LangGraph configurable；恢复时读取同一份已固定快照，不重新解析 active pointer。

API：
- `POST /api/platform/v1/registry/{kind}/{item_id}/versions`
- `POST /api/platform/v1/registry/{kind}/{item_id}/versions/{version}/publish`
- `POST /api/platform/v1/registry/{kind}/{item_id}/rollback/{target_version}`
- `POST /api/platform/v1/registry/{kind}/{item_id}/disable`
- `GET /api/platform/v1/registry/{kind}/{item_id}/versions`
- `GET /api/platform/v1/registry/{kind}/{item_id}/active`

## 3. 会话与文件资产（#8）

代码：
- `agent_platform/control_plane/sessions_assets.py`
- `agent_platform/control_plane/postgres.py`：`PostgresSessionRepository`
- `agent_platform/api/sessions.py`

边界：
- PostgreSQL 保存会话、消息和文件资产元数据；二进制内容通过 `ObjectStorage` 端口保存。
- `InMemoryObjectStorage` 仅供测试，不是生产持久化实现。
- 文件上传执行大小限制、媒体类型策略、文件名路径清理、SHA-256、扫描器接入和下载完整性校验。
- 扫描拒绝或扫描器异常时文件标记 rejected 并清理对象；元数据写入失败时补偿删除对象。
- 文件绑定会话时继承会话 project_id；不允许将文件绑定到与会话不一致的项目。
- 人类会话 API 仅接受 user role；assistant/tool/agent/system 消息由受信任执行链路写入，防止客户端伪造助手结果。
- 文件引用需要独立资源授权；会话和项目授权由宿主注入。

## 4. 外部数据连接器（#8）

代码：
- `agent_platform/control_plane/data_connectors.py`
- `agent_platform/control_plane/postgres_connectors.py`
- `agent_platform/api/connectors.py`

能力：
- Provider、SecretResolver、ConnectorSink 均为注入端口，不在平台代码中硬编码第三方凭据。
- 凭据仅以 `secret://...` 引用持久化，执行时由 SecretResolver 解析。
- 增量同步使用 cursor + version compare-and-swap，避免并发 Worker 覆盖游标。
- Sink 必须按 tenant_id + connection_id + provider item ID 幂等 upsert；游标 CAS 失败时允许安全重放。
- 本地撤销立即生效，阻止后续同步；可选择 retain/delete 处理已同步数据。
- 远端 OAuth 撤销失败不恢复本地授权，错误写入 last_error；重复调用撤销接口会重试远端撤销和 Sink 清理，清理端必须按 connection_id 幂等。

API：
- `POST /api/platform/v1/connectors`
- `POST /api/platform/v1/connectors/{connection_id}/revoke`

## 5. 数据迁移

- `011_registry_sessions_assets.sql`：注册版本、active pointer、会话、消息、文件资产、连接器元数据。
- `012_connector_sync.sql`：连接器游标并发版本和错误信息。
- `014_run_registry_snapshot.sql`：Run 固定注册版本快照。

所有 migration 使用递增编号，按序执行；不得重建现有业务表。
