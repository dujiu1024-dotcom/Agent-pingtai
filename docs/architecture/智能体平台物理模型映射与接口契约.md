# 智能体平台物理模型映射与接口契约

- 版本：v1.0
- 日期：2026-11-15
- 适用分支：`refactor/agent-platform-v1`
- 状态：设计基线；新增业务表按所属 Issue 分阶段实施，不在本文件中伪装为已实现

## 1. 使用原则

1. 本文件区分三种状态：**已落库**（迁移脚本中存在）、**已有契约/实现但未形成完整平台持久化**、**规划新增**。不能根据领域实体名称推断代码已实现。
2. PostgreSQL 是平台业务事实源。Redis Streams 只负责事件分发；Outbox 记录与业务变更在同一 PostgreSQL 事务内提交。
3. 所有租户业务表必须带 `tenant_id`，唯一键、外键和查询条件必须包含租户维度。跨租户全局目录必须显式定义平台级作用域。
4. Agent/Workflow/Model/Tool/Skill/Prompt 等可变配置采用不可变版本；Run 创建时固化引用版本与配置摘要。
5. 本文只定义逻辑接口和持久化目标；具体 HTTP 路由、请求 DTO 和数据库 Repository 由 #6—#20 分项实现。

## 4. 关键数据库约束

### 4.1 租户隔离
- 所有租户业务表使用 `tenant_id NOT NULL`。
- 租户内唯一键采用 `UNIQUE (tenant_id, business_key)`。
- 跨表引用优先使用包含 `tenant_id` 的复合外键；无法建立复合外键时，Repository 必须在事务内校验租户归属。
- 后台任务、事件消费、向量检索都必须显式携带 tenant_id；禁止依赖调用方遗漏时的默认租户。
- 后续可评估 PostgreSQL RLS 作为纵深防御，不以 RLS 取代服务层授权。

### 4.2 版本与快照
- 版本表采用 `(tenant_id, object_id, version)` 复合主键。
- 已发布版本不可原地修改；修改产生新版本。
- Run 保存 AgentVersion、WorkflowVersion、ModelTemplateVersion、Tool/Skill/Prompt 版本引用，以及配置摘要/哈希。
- 历史 Run 不因 Registry 当前版本变化而改变可复现配置。

### 4.3 删除、审计与幂等
- 普通业务对象使用 `deleted_at` 软删除；身份撤销、授权回收应立即生效。
- 隐私删除按数据治理策略清理原文、派生文本、Embedding、缓存和对象存储；备份按保留周期到期清除或销毁密钥。
- AuditEvent、Blackboard Decision、Outbox Event 采用追加写；纠错通过新记录表达。
- 外部副作用使用调用方生成的 `idempotency_key`，并对 (tenant_id, idempotency_key) 建唯一约束。
- 平台只承诺至少一次事件投递和消费端幂等，不宣称跨系统 exactly-once。

### 4.4 索引基线
- 业务列表：`(tenant_id, status, created_at DESC)`。
- 资源归属：`(tenant_id, project_id, created_at DESC)`。
- Run 查询：`(tenant_id, status, created_at DESC)` 与必要的 task_id/agent_id 索引。
- Outbox：仅索引未发布记录，并支持租约/重试字段扫描。
- 向量检索：向量索引与 tenant/resource ACL 过滤配合；不能先全局召回再在 UI 过滤。
- 所有索引须由实际查询计划和数据规模验证，不预先堆叠低价值索引。

## 5. 应用层接口契约

接口采用 Python Protocol/应用服务端口表达；HTTP DTO、数据库实现和 SDK 属于适配层。下列契约中的 tenant_id、actor_id、resource scope 不得由模型输出决定。

| 契约 | 核心操作 | 输入上下文 | 返回/失败语义 | 数据归属 |
|---|---|---|---|---|
| IdentityService | authenticate、authorize、resolve_membership | tenant、actor、resource、action | 身份无效/授权拒绝明确失败；默认拒绝 | Identity |
| RegistryService | get_version、publish、deprecate、resolve_snapshot | tenant、object_id、version | 不存在/未发布版本拒绝；发布不可变 | Registry |
| TaskRunService | create_task、start_run、pause、resume、cancel、get_status | tenant、actor、task/run、idempotency_key | 状态迁移冲突返回 Conflict；终态不可回退 | Task/Run |
| RuntimeAdapter | run、stream、cancel、capabilities | RunContext、固定版本快照、超时/取消信号 | 统一 HarnessResult；不支持能力显式 unsupported | Runtime |
| WorkflowRunner | start、resume、interrupt、cancel | WorkflowVersion、checkpoint、RunContext | checkpoint 不可序列化时不得伪称可恢复 | Orchestration |
| BlackboardRepository | propose、get、list、revise、challenge、decide | tenant、scope、actor、expected_version | 版本冲突抛 VersionConflict；事件与 Outbox 同事务 | Blackboard |
| KnowledgeRetriever | ingest、retrieve、delete、reindex | tenant、actor、project/resource ACL、query | 返回 chunk、source、version、ACL decision、score；未授权不返回 | Knowledge |
| MemoryService | extract、upsert、retrieve、supersede、expire、delete | owner scope、source refs、consent/policy | 支持来源追溯、置信度、过期和删除 | Memory |
| ToolGateway | list_allowed、execute | Trusted RunContext、ToolVersion、arguments、idempotency_key、approval | 未注册/无权/审批不匹配拒绝；审计失败不执行 | Tools/Governance |
| FileService | create_upload、get_download_handle、delete | tenant、actor、resource ACL、checksum | 只返回短时授权句柄，不暴露宿主路径 | File |
| EventPublisher | append_outbox、publish_pending | tenant、event_id、topic、payload | Outbox 先落库；发布可重试；消费回执去重 | Events |
| EvaluationRunner | run_dataset、compare、report | 固定 Agent/Prompt/Model/Workflow 版本和 Dataset 版本 | 记录评分规则、原始结果、成本与 Trace | Evaluation |
| UsageMeter | record_usage、aggregate、check_budget | tenant、run、provider/model、token/cost dimensions | 重复事件幂等；预算超限按策略阻断/告警 | Usage/Budget |

## 6. 事务边界与事件一致性

1. 业务写入与 Outbox 插入处于同一 PostgreSQL 事务。
2. Relay 通过租约领取待发记录，向 Redis Streams 发布后标记完成；租约丢失可能产生重复发布。
3. Consumer 以 event_id 建立持久化回执；业务副作用与回执在同一事务时优先同事务提交。
4. 外部 API、邮件、消息推送等不可与本地事务原子提交，必须使用幂等键、重试和必要的补偿状态。
5. Redis 不可用时，业务事务仍可写入 Outbox；恢复后继续投递。
