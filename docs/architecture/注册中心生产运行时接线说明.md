# 注册中心生产运行时接线

关联：Issue #7

## 运行时原则

- Run 在启动前固定 Agent、Workflow、Model Template、Model Provider、Tool 和 Skill 的已发布版本；运行时不得读取 registry 的 latest 指针。
- 模型路由只解析 Run Snapshot 中固定的 Model Template / Provider 版本。API Key 通过宿主 SecretResolver 在调用时读取，不写入快照、LangGraph 状态或日志。
- 模型故障降级必须显式列出同一 Run Snapshot 中的 fallback template；不允许静默切换到最新模型或其他租户的配置。
- 工具定义中的风险等级、JSON Schema、允许角色来自已发布 Tool Registry 版本；handler、资源解析器和授权器只能由宿主可信代码注入。
- Skill 的依赖必须经过精确版本 allowlist 和供应链扫描。扫描器未配置、不可用或发现 advisory 时，Skill 审查拒绝通过。
- MCP 健康检查通过宿主提供的可信 SessionFactory 建立真实协议会话，执行 ping 并核对远端工具清单；只保存健康状态和错误类别，不保存 endpoint、Authorization 或异常原文。

## 模型路由接线

1. 在宿主组合根创建 `RegistryModelResolver(secret_resolver)`。
2. 创建 `OpenAICompatibleHTTPTransport` 和 `OpenAICompatibleModelRouter`，注入持久化 UsageRecorder。
3. 创建 `RegistryRuntimeAssembler`，传入 RunRegistrySnapshotService、model router、SkillDependencyReviewer 和可信工具 handler 映射。
4. Run 开始时调用 `assemble(tenant_id, run_id, model_template_id)`，将返回的可信 ToolDefinition 注册到本次 Run 的 Gateway；模型节点使用返回的 `RunScopedModelClient`。
5. 每次模型调用都重新读取不可变 Run Snapshot，再解析 secret_ref；明文 API Key 只存在于单次请求对象内。
6. 若需要降级，调用时传入显式 fallback template IDs；这些 ID 必须已经存在于同一个 Run Snapshot。

HTTP transport 使用标准库 HTTPS 请求，默认校验证书、拒绝重定向、限制响应大小，并对 provider 错误做脱敏。请求参数不能覆盖 model、messages、tools、Authorization 或 base_url。

## MCP 健康检查接线

- 为每个已注册 MCP Server 提供 `SessionFactory(tenant_id, server_id)`；Factory 必须从宿主 SecretResolver 取凭据，不接受 Registry 中的任意命令或可执行配置。
- 调用 `MCPHealthChecker.check`，传入 Registry 声明的预期工具名。
- 健康状态只在 ping 成功且远端工具清单与 Registry 完全一致时标记 healthy；超时、协议错误和清单漂移均标记 unhealthy。
- 生产环境使用 `PostgresMCPHealthStore`，部署前应用 migration `024_registry_runtime_governance.sql`。

## Skill 依赖审查接线

- 创建 `SkillDependencyReviewer` 时必须提供组织批准的 package/pin allowlist 和供应链 AdvisoryScanner。
- 对已发布 Skill Version 调用 `review(item, actor_id)`；只允许精确匹配 allowlist 且扫描无风险的版本获得 approved。
- Run Runtime Assembler 对快照中的每个 Skill 检查审核记录与 manifest digest；缺失、拒绝或过期记录均阻止 Run 组装。
- 生产环境使用 `PostgresSkillDependencyReviewStore`，与 MCP 健康状态共用 migration 024。

## LangGraph Worker 自动接线

- 创建 `RegistryRuntimeProvider(assembler)`，将同一个 Provider 注入 LangGraph 节点闭包和 `LangGraphRunExecutor`。
- 创建 Executor 时传入 `registry_runtime_provider`、`model_template_id` 和 `required_tools`。
- Executor 在 QUEUED Run 转入执行后、调用图之前执行 `prepare`；图节点通过 Provider 的 `get(tenant_id, run_id)` 取得本次 Run 的模型客户端和可信工具定义。
- 正常结束、异常、超时、取消和租约丢失后都会释放 Worker 本地运行时缓存。
- Worker 恢复时会从 PostgreSQL Run Snapshot 和依赖审核仓储重新组装运行时，再恢复原 LangGraph Checkpoint；不会恢复旧进程的内存对象或密钥。
- Worker 进程重启后，内存 Runtime Store 为空是预期行为；必须先重新 `prepare`，再允许图节点取得运行时上下文。

## 生产配置与验收边界

- 需要宿主注入：SecretResolver、UsageRecorder、MCP SessionFactory、依赖 allowlist、AdvisoryScanner、可信 Tool handler/resource authorizer。
- 需要部署环境提供：PostgreSQL migration 024、模型供应商 HTTPS endpoint、Vault/KMS secret_ref、MCP Server 访问网络。
- 自动化测试覆盖固定版本解析、显式 fallback、数据等级限制、请求参数防覆盖、MCP 工具清单漂移、Skill allowlist/advisory 和 Runtime 组装。
- 本仓库不预置任何真实模型 API Key、MCP 地址、第三方包源或供应链白名单；这些属于租户/运维配置，不能以测试值冒充生产配置。
- 真实模型调用、MCP 网络探测、Vault/KMS、供应链扫描服务和部署连通性留待用户现场验证。
