# 知识库与记忆服务实现说明

实现位置：`agent_platform/knowledge`、`agent_platform/memory`；数据迁移：`agent_platform/storage/postgres/006_knowledge_memory.sql`。

## 知识库（Issue #10）
- 文档以 tenant + document + version 为主键；记录来源 URI、内容哈希、可见范围和元数据。
- 文本/Markdown、HTML 使用标准库解析；PDF、Office、扫描件 OCR 通过可选解析器适配器接入，未安装时明确失败。
- 切片保留原文偏移、序号、页码扩展字段和内容哈希。
- PostgreSQL 保存文档/切片；全文检索使用 tsvector/GIN，向量使用 pgvector；Embedding、Rerank 通过端口注入。
- PostgreSQL 检索在 SQL 内执行 tenant、project、private-owner 和显式 ACL 过滤，未经授权的 chunk body 不会离开存储层。
- 引用返回 document_id、document_version、chunk_id、source_uri、offset/page 与 retrieval trace。
- 旧 `vectors.py` 保留为存量适配对象；新平台不依赖其 SQLite/向量表结构，迁移时按原文重新解析、切片、索引，不将旧向量当作权威来源。

## 记忆（Issue #11）
- 作用域 user / agent / project / tenant；与 Knowledge、Blackboard、Conversation 分离。
- 提取只生成 candidate；只有经确认才进入 active 检索，禁止聊天全文无差别写入长期记忆。
- 记录来源、置信度、创建者、确认者、版本、过期时间和适用范围；支持拒绝、检索和软删除。
- 删除回调用于传播到缓存/派生索引；原始记忆记录保留删除审计。

## 验证与已知限制
运行 `python -m unittest tests.test_knowledge_service tests.test_memory_service -v`。
PDF/Office/OCR 解析器需要按部署选型安装并做真实样本验收；pgvector/全文混合召回、embedding 批量写入、数据库级 ACL 负向测试仍需服务级 CI 覆盖，不能仅凭 migration 文件宣称生产就绪。
