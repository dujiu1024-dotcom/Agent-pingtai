# 人工审批生命周期与执行网关集成

## 已有安全底座

- Tool Gateway 使用可信工具注册表决定风险等级；未知工具拒绝。
- 高风险外部副作用要求一次性审批，审批摘要绑定动作、资源、操作者和参数。
- PostgreSQL 消费审批时按 tenant、approval_id、action_hash、approved 状态和有效期原子更新。
- 审计写入失败会阻止工具执行；审计表由数据库触发器禁止普通 UPDATE/DELETE/TRUNCATE。
- OCI 沙箱要求 digest 固定镜像、无网络、只读根文件系统、非特权用户、丢弃 capabilities、资源限制且不挂载宿主机目录。

## 本次补齐

新增审批生命周期服务和 HTTP API：
- 创建审批只接受风险级别 2/3；TTL 限制为 24 小时以内。
- 待审批列表仅对服务端授权的审批人开放，并按租户隔离。
- 申请人不能批准自己的申请。
- 决策仅允许 pending 且未过期记录；数据库更新条件保证并发决策只有一次成功。
- API 不接受调用方指定 tenant_id、requested_by 或 decided_by；均取认证主体。
- 平台组合工厂要求审批服务和审批人授权器同时配置，能力发现仅在两者都存在时声明 approvals=true。

## 执行约束

审批通过后，执行仍必须经过 Tool Gateway 的 action_hash 校验与一次性消费；不能绕过 Gateway 直接执行。风险级别 3 仍保留人工直接执行边界，不因审批记录而自动放行。

## 未由代码替代的现场验收

容器运行时配置、宿主机/网络隔离、密钥托管与轮换、真实审批工作台交互和生产审计权限需在部署环境验收。部署/真机/演练验证跳过，标注「待用户真机验证」。


## 密钥生命周期与 Secret Manager 接口

新增 `agent_platform.security.secrets.SecretManager`，以 `secret://{tenant}/{path}` 引用作为业务接口。密钥明文只进入注入的 Vault/KMS `SecretBackend`，PostgreSQL `platform_secret_versions` 仅保存引用、版本、状态和时间，不保存密钥值。支持 create、rotate、resolve、describe、revoke；轮换先创建新版本并原子激活，再撤销旧后端版本；元数据激活失败时撤销新版本；无唯一 active 版本或后端取不到 active secret 时 fail closed。列表/describe 只返回元数据，不回显密钥。生产 Vault/KMS 驱动与凭据策略仍由部署环境注入，未配置生产后端不得将测试替身当作生产 Secret Manager。
