## 1. 本轮实现

### 1.1 OCI 执行隔离

`agent_platform/sandbox/oci.py` 提供 Docker/Podman OCI runner。每次执行创建一次性容器，固定执行约束：

- 镜像必须使用 SHA-256 digest 固定，禁止 `latest` 或可变 tag。
- `--network=none`，默认无网络。
- `--read-only`，根文件系统只读。
- `--cap-drop=ALL`、`no-new-privileges`，以非 root UID/GID 运行。
- 设置 CPU、内存、PID、tmpfs 和执行超时上限。
- 不挂载宿主机目录、设备、Docker Socket，不共享宿主机 PID/IPC/网络命名空间。
- 容器环境变量默认空；只允许显式 allowlist，且禁止 Secret/Token/Password/API Key 类键。
- 命令以 argv 数组传递，不经过 Shell；stdin/stdout/stderr 均有执行超时和输出大小控制。

该 runner 通过 `agent_platform/sandbox/lifecycle.py` 暴露为 Tool Gateway 的 ContextualToolHandler。调用必须携带受监督 Run 上下文，且通过 Run 级 ToolCallRegistry 注册；Run 取消时会向运行时发送终止信号并等待清理。工具风险等级仍由服务端可信注册表配置，审批验证与写前审计由 SupervisedToolGateway 执行。Harness 只能通过宿主侧受信任执行服务调用，不得获得 Docker/Podman Socket 或宿主机凭据。

### 1.2 审计记录追加写保护

PostgreSQL migration `011_audit_append_only.sql` 为 `platform_tool_audit` 和 `platform_identity_audit` 添加 UPDATE/DELETE 行级拒绝触发器和 TRUNCATE 语句级拒绝触发器，并撤销 PUBLIC 的 UPDATE/DELETE/TRUNCATE 权限。

运行时数据库账号必须满足：
- 不是迁移表的 Owner；
- 不拥有 DDL、ALTER、DROP、TRIGGER 或角色管理权限；
- 只获得业务所需的 INSERT/SELECT 权限；
- 迁移账号与运行时账号分离，迁移凭据不得注入 Agent/Harness。

触发器保护不能抵御数据库超级用户或表 Owner 主动禁用触发器，因此生产环境必须通过独立迁移身份、最小权限和数据库审计保护该边界。

## 2. 使用约束

1. 生产必须使用 rootless Docker/Podman 或经安全评审的等效运行时。
2. OCI daemon 不得暴露给 Agent；不得将运行时 Socket 挂入容器。
3. 沙箱镜像需经过依赖扫描、签名/来源校验并固定 digest。
4. 默认不向沙箱注入模型密钥、数据库凭据、云凭据或控制面 Token。
5. 需要访问平台资源时，必须由宿主侧 Tool Gateway 代理，且仍执行租户授权、风险分级、审批和审计。
6. 沙箱输出视为不可信输入，返回平台前需做大小限制、格式校验和敏感信息扫描。
7. OCI 容器隔离不是完整虚拟机边界；高风险多租户不可信代码应评估 gVisor、Kata Containers 或独立微虚拟机。
