# 数据迁移批次与删除生命周期治理增量

## 权威写入方矩阵

| 数据对象 | 当前来源 | 目标系统 | 迁移方式 | 切换前权威写入方 |
|---|---|---|---|---|
| 用户与外部身份 | 旧 users / open_id | platform_users / external identities | 人工映射认领 | 旧系统 |
| 项目/成员 | 旧 projects | Tenant/Project/RBAC | 批次导入与只读差异核对 | 旧系统 |
| 会话/消息 | conversation.py / SQLite | Session/Message 服务 | Adapter + 批次迁移 | 旧系统 |
| 工作记忆 | memory.py / wm_session | MemoryService | 分类、去重、用户确认后导入 | 旧系统 |
| 文档/向量 | vectors.py / 旧文件 | Knowledge DocumentVersion/Chunk/Embedding | 文档重解析与向量重建 | 旧系统 |
| 文件 | 旧路径/附件 | 对象存储 + 文件元数据 | 内容哈希、权限和引用校验 | 旧系统 |
| 审批/审计 | 旧审计记录 | append-only 平台审计 | 只读历史导入 | 旧系统 |
| 凭据 | 旧配置/Token | Secret Manager 引用 | 重新授权，不迁移明文 | 旧系统 |

切换时必须在变更单中记录权威写入方切换时刻；任何批次均不得同时向源和目标双主写入。

## 迁移批次台账

新增 `platform_data_migration_batches` 与 `platform_data_migration_rows`：
- 每个租户、批次唯一。
- 批次记录源/目标系统、对象类型、状态、数量和校验摘要。
- 行级记录 source_key、target_key、payload_hash 和处理状态。
- source_key 唯一约束支持重复执行；内容哈希用于识别源记录变化。
- 状态包括 planned/running/validated/switched/rolled_back/failed；行状态包括 pending/imported/validated/skipped/failed。

`migration_fingerprint` 对规范化 payload 生成稳定 SHA-256 幂等键。

## 删除与保留

`DeletionCoordinator` 对配置的 PostgreSQL、对象存储、向量索引、缓存、连接器副本等适配器执行同一 operation_id。单个系统失败不会被报告为整体成功；返回已完成和失败系统。重试时传入已完成系统清单，跳过成功目标并重试失败目标。适配器必须以 operation_id 实现幂等删除。

保留策略显式定义对象类型、保留期限、软删除窗口和法律保留支持。法律保留审批应在调用协调器之前完成。
