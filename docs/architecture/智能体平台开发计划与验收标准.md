# 智能体平台开发计划与验收标准

- 版本：v1.0
- 日期：2026-11-15
- 执行方式：Issues 驱动；模块可并行；集成验收统一把关

## 1. 阶段计划

| 阶段 | 目标 | Issues | 退出条件 |
|---|---|---|---|
| P0 设计基线 | 能力、领域模型、模块契约、选型、迁移和验收标准冻结 | #5 | 文档一致、决策可追溯、接口/实体/验收明确 |
| P1 控制面 | 身份权限、资源注册、会话文件、任务运行 | #6—#9 | 核心 API、租户隔离、状态机和管理操作可用 |
| P2 智能体核心 | 知识库、记忆、Runtime、Blackboard、UI | #10—#14 | Agent 从配置到执行、知识增强、审批和结果展示闭环 |
| P3 治理运营 | 安全、审计、评测、可观测、成本 | #15—#17 | 关键安全负向测试、成本归集、评测门禁可运行 |
| P4 生产化 | 部署、迁移、开放 API、故障演练 | #18—#21 | 可部署、可恢复、可迁移、端到端验收通过 |

## 2. 并行规则
- #5 是领域和契约基线；#6—#9 可先以契约草案并行，但不得在实体未冻结前自行创建冲突模型。
- #10/#11 可并行，必须明确 Knowledge、Memory、Blackboard 边界。
- #12 Runtime 与 #13 Blackboard 通过协议并行；工具统一 Gateway。
- #14 UI 可先基于 API 契约和 Mock 并行。
- #15—#17 应从早期参与设计评审，不得拖到最后才补安全。
- #18/#19 可提前编制方案；生产切换必须等对应迁移验收。
- #21 汇总全链路验收，不替代各 Issue 自身测试。

## 3. 通用交付要求
每个 Issue 必须交付：
1. 设计/契约更新（若有边界变化）。
2. 实现代码与数据库迁移（若涉及持久化）。
3. 单元测试、集成测试和必要的安全负向测试。
4. 可重复执行的验证命令及结果。
5. 运行/部署/回滚说明。
6. 变更影响、未完成项和技术债记录。

## 4. Definition of Done
- 需求覆盖：Issue 范围逐项映射到实现和测试。
- 安全：鉴权、租户隔离、输入校验、密钥脱敏和工具授权经过验证。
- 可靠性：重试/幂等/超时/取消/恢复按能力声明工作。
- 可观测：关键链路有 Trace、结构化日志和错误指标。
- 数据：迁移有版本、索引、约束和回滚策略。
- 文档：配置、部署、操作、故障排查文档同步。
- CI：相关测试通过；失败必须记录，不可通过跳过测试伪造通过。
- 证据：关闭 Issue 前附 PR、测试结果和验收记录。

## 5. 平台级端到端验收
1. 用户登录并加入租户/项目，越权请求被拒绝。
2. 管理员注册模型模板、工具、Skill、Agent 和工作流版本。
3. 用户创建会话并提交任务，平台创建 Task/Run 并固定版本快照。
4. Agent 在授权知识库检索，返回引用、文档版本和来源定位。
5. 多专家通过 Blackboard 提案、证据、质疑和裁决收敛结果。
6. L2 工具动作暂停等待审批；参数改变后审批失效。
7. 运行可暂停、恢复、取消；Worker 崩溃后可安全接管。
8. Trace、Token、成本、审计记录可按一次运行串联查询。
9. 用户可查看产物、纠正结果并重新执行。
10. 完成备份恢复、数据导出/删除、迁移回滚演练。

## 6. 发布门禁
- 单元/集成/端到端测试达到项目阈值；安全关键用例零失败。
- 租户隔离、工具越权、审批绕过、知识库 ACL 过滤等负向测试必须通过。
- 数据库迁移在空库安装和上一版本升级两条路径均通过。
- 关键性能指标、成本预算和降级策略有实测记录。
- 无未处理的 Critical/High 安全问题；风险接受需有责任人和到期日。
