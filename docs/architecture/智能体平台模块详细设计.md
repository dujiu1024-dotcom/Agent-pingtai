# 智能体平台模块详细设计

- 版本：v1.0
- 日期：2026-11-15
- 架构形态：模块化单体；必要时再拆服务

## 1. 模块边界与依赖方向

| 模块 | 职责 | 允许依赖 | 禁止事项 |
|---|---|---|---|
| api | HTTP/API、认证中间件、请求校验 | application、identity | 直接访问模型/数据库表 |
| identity | 用户、租户、成员、授权决策 | domain、repository | 依赖 Agent Runtime |
| registry | Agent/Workflow/Model/Tool/Skill/Prompt 版本注册 | domain、repository | 执行 Agent |
| application | 用例编排、事务边界 | domain、ports | 持有外部 SDK 细节 |
| orchestration | LangGraph 工作流定义、状态和检查点 | application、runtime ports | 替代 Blackboard |
| runtime | Harness Adapter、上下文、委派、输出校验 | tool gateway port、model port | 绕过网关调用工具 |
| blackboard | 多专家共享条目、证据、冲突、决策 | domain、repository、events | 保存全部聊天历史 |
| knowledge | 文档接入、解析、切片、检索、ACL、引用 | storage、embedding/rerank ports | 未授权片段进入模型上下文 |
| memory | 记忆提取、生命周期、检索、删除 | domain、repository | 把全部对话无差别永久保存 |
| tools | Tool Gateway、MCP Adapter、审批与审计钩子 | identity、policy、audit | 由模型决定风险级别 |
| governance | policy、approval、audit、quota、secret refs | identity、repository | 明文密钥落库/日志 |
| observability | trace、metrics、logs、evaluation、alerts | event hooks、Langfuse adapter | 采集明文敏感数据 |
| storage | PostgreSQL、Redis Streams、对象存储适配 | infrastructure only | 业务决策 |
| migration | 旧系统 Adapter、导入导出、校验和切换 | old-system ports、domain | 双主写 |

## 2. 请求执行主链路
1. API 接收请求并验证身份、租户、项目和资源权限。
2. Application 创建 Task/Run，固定所有配置版本快照。
3. Orchestration 按 WorkflowVersion 启动 LangGraph；简单任务可直接请求 Runtime。
4. Context Builder 组装系统指令、用户输入、项目上下文、记忆和授权知识片段，执行 Token 预算与压缩。
5. Runtime Adapter 调用选定 Harness；所有工具调用通过 Tool Gateway。
6. Gateway 做身份、资源 ACL、Schema、风险级别、限流和审批校验，并记录调用前后审计。
7. 多专家协作通过 Blackboard 提案/证据/质疑/冲突/裁决，事件经 Outbox 发布。
8. 输出执行结构化 Schema 校验；失败按策略修复重试或返回明确失败。
9. Run/Task 状态、产物、Usage、Trace 和评测信息持久化。
10. 用户可查看过程、取消/暂停/恢复、补充上下文或审批。

## 3. 关键契约
- RuntimeAdapter：声明支持的流式、取消、超时、工具、结构化输出、多模态和恢复能力；不支持的能力明确返回 unsupported。
- ToolGateway：接收可信 RunContext、ToolVersion、参数和幂等键；风险级别来自注册数据；输出审计结果。
- KnowledgeRetriever：输入 tenant/user/project/resource context，输出片段、来源定位、版本、权限判定和检索分数。
- MemoryService：按作用域、来源、置信度、时间、过期和权限读写记忆。
- WorkflowRunner：以固定版本执行，支持检查点、人工中断、恢复和取消。
- EventPublisher：先写 PostgreSQL Outbox，再异步发布 Redis Streams；消费端持久化幂等回执。
- FileService：只暴露授权后的文件句柄，不向 Agent 直接暴露宿主机路径。
- EvaluationRunner：固定数据集、模型模板、Prompt、Agent 版本和评分规则，产出可复现报告。

## 4. 运行状态机
Task：draft → queued → running → blocked/needs_input → completed/failed/cancelled。
Run：queued → running ↔ paused → succeeded/failed/cancelled/expired。
状态迁移必须通过领域服务校验；终态不可直接回退，重跑创建新 Run 并关联 parent_run_id/retry_of。

## 5. 运行可靠性
- Worker 通过租约领取任务；租约过期允许其他 Worker 接管。
- 每次副作用调用传递 idempotency_key；平台记录调用结果。
- 重试按错误类别区分可重试/不可重试；指数退避和最大尝试次数可配置。
- 取消是协作式取消；工具调用需传播取消信号，不能承诺强制中断所有外部系统。
- 暂停恢复依赖可序列化 checkpoint；不能序列化的 Runtime 状态不得假装可恢复。
- 失败补偿必须显式建模；不以重复调用实现补偿。

## 6. 上下文与输出治理
Context Builder 预算按模型模板的上下文限制分配：系统指令、任务目标、最新对话、项目资料、记忆、知识片段和输出预留分别设预算。压缩摘要需保留目标、约束、关键决策、证据引用、未完成事项；原始来源可回溯。
结构化输出通过 JSON Schema/Pydantic 等标准校验；Schema 带版本；最多有限次修复重试，失败保留原始输出和校验错误。

## 7. 安全边界
- 所有资源访问先做租户和资源授权。
- Runtime 无数据库凭据；工具权限由 Tool Gateway 执行。
- Harness 执行沙箱与平台控制面隔离；网络默认拒绝，按工具代理白名单开放。
- Secret 通过引用注入短期凭据，禁止进入 Prompt、Blackboard、Trace 和日志。
- 用户输入、检索文档和工具输出均视为不可信内容，需防 Prompt Injection。
- 高风险操作审批绑定参数摘要、目标资源、操作者和有效期。

## 8. 旧系统兼容
旧系统能力通过 Adapter 迁移；新模块不直接 import 旧单体模块。迁移期间定义每类数据唯一写入方，详见《新旧系统迁移方案》。
