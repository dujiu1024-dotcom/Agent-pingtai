# 旧身份账户认领与导入流程

关联：Issue #6（平台基础与产品控制面）
状态：实现了显式映射、预检和事务导入；真实数据迁移必须在正式切换窗口由运维执行。

## 安全原则

- 旧 SQLite 数据库以只读模式打开；导入器只读取 open_id、name、role、projects，不读取 console_token。
- 不从旧 open_id 推断邮箱、用户身份或身份提供方。必须人工指定 provider，并把每条旧账户映射到一个已存在、已激活且属于目标租户的 platform user UUID。
- 旧 role 必须逐项映射到目标租户已存在的 role_id。可显式映射为 null，代表不授予该层级权限；不得自动把旧 admin 字符串提升为 tenant_admin。
- 项目成员关系与项目 RBAC 分离。导入项目成员不等于授权；只有显式提供 project_role_id 才会建立项目角色绑定。
- 不导入旧 console_token，不创建密码，不自动注册用户，不触碰真实用户库。
- 所有外部身份、成员关系、角色绑定和审计记录在同一 PostgreSQL 事务中提交；已被其他用户认领的外部身份直接拒绝。

## 1. 生成映射模板

    python -m agent_platform.identity.legacy_migration \
      --db /path/to/legacy.sqlite \
      --template-output /path/to/identity-mapping.json \
      --tenant-id tenant-123 --provider wechat-work

模板以旧 open_id 的 SHA-256 前 16 位作为 legacy_subject_ref，不输出原始 open_id 或 Token。逐条填写 accounts.<ref>.user_id，并为每种旧角色填写 role_mappings.<legacy_role>.tenant_role_id 和可选 project_role_id。目标用户必须已在新平台创建并加入目标租户。

## 2. 预检

    python -m agent_platform.identity.legacy_migration \
      --db /path/to/legacy.sqlite \
      --mapping /path/to/identity-mapping.json

默认只构建计划，不写入 PostgreSQL。预检会拒绝缺少身份认领、缺少角色映射、重复旧身份、未知映射键、无效 UUID、缺失 provider 或 tenant_id。

## 3. 执行导入

    python -m agent_platform.identity.legacy_migration \
      --db /path/to/legacy.sqlite \
      --mapping /path/to/identity-mapping.json \
      --apply --dsn "$PLATFORM_DATABASE_URL" \
      --confirm IMPORT-LEGACY-IDENTITIES

导入器要求目标用户和租户成员均为 active；要求映射的角色、项目属于目标租户；按 provider + provider_subject 绑定外部身份；为项目创建成员关系；按显式角色映射建立租户/项目 RoleBinding。重复执行不会重复创建外部身份、项目成员或有效角色绑定。任何一条记录失败都会回滚整批事务。

## 4. 切换前检查

1. 完成旧用户只读盘点并审阅所有身份认领和角色映射。
2. 先部署新平台并确认至少一个新平台 Tenant Owner 可登录。
3. 在备份后执行导入；核对导入计数、角色绑定和审计记录。
4. 在维护窗口停用旧 Console Token 认证，并按旧 Token 作废流程先备份再清理。
5. 保留迁移报告、映射文件审批记录、导入输出和 PostgreSQL 审计记录。

本工具不会自动执行第 2—4 步，也不会在未提供显式确认时写入目标数据库。
