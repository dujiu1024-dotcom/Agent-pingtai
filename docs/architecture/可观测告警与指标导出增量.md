# 可观测告警与指标导出增量

本增量补齐两项平台基础设施：

## Prometheus 指标端点

- 路径：`GET /api/platform/v1/observability/metrics`
- 仅在平台组合工厂显式传入 `metrics_exporter` 时挂载。
- 必须经过身份中间件，要求已认证用户主体。
- 输出 Prometheus text exposition 0.0.4。
- 未配置 exporter 返回 503；匿名访问返回 401。
- 生产部署应为抓取账号配置最小权限，或由受控内网代理转发；不要把指标端点无认证暴露到公网。

## 告警规则引擎

`AlertManager` 支持确定性阈值规则、比较符、严重级别、冷却抑制和通知端口。当前由调用方显式传入指标快照并触发 evaluate，不启动后台线程、不隐式访问网络。生产环境应由调度器定期拉取队列、模型、工具和运行指标，再接入实际通知渠道。

## 仍待完成

- 真实 Prometheus/OpenTelemetry exporter 和生产服务发现。
- 队列积压、模型超时、RAG 质量、工具拒绝等各组件的完整指标埋点与告警规则配置。
- 通知渠道、告警聚合、维护窗口、故障责任人和工单处理闭环。
- 真实 Agent/RAG 回归集、人工评分、模型对比及发布门禁；PromptRegistry 当前仍是内存实现。
- Langfuse 自托管连接、保留策略与权限隔离现场验收。

部署/真机/演练验证跳过，标注「待用户真机验证」。单元测试提交不等于生产告警验收。


## 持久化告警记录补充

`PostgresAlertEventStore` persists alert events by scope and dedupe key, supports open/acknowledged/resolved lifecycle, and makes duplicate delivery idempotent. The notification transport remains an injected port; deployment-specific channels and on-call routing are configured outside the core engine.

## 生产 Prometheus 指标后端

新增 `PrometheusClientMetricsRecorder`，使用独立的 `CollectorRegistry` 导出 Counter 与 Histogram；与 `ObservedHarnessAdapter` 使用的 `increment/observe/render_prometheus` 契约兼容。部署时将同一个 recorder 实例传入 `create_platform_app(metrics_exporter=...)`，即可由受身份保护的指标路由导出真实 Prometheus 指标。

- 生产依赖：`prometheus-client>=0.21,<1.0`，只加入平台可选依赖，不影响纯标准库 CLI。
- 同一指标名固定类型和标签名集合，避免不同调用方动态改变指标结构。
- 仅允许 `component/status/model_template/finish_reason/operation` 标签；禁止 tenant、user、run、request、prompt 等高基数标识符。
- Counter 和 Histogram 分别导出，观测值包含 bucket/count/sum。
- 指标值必须为有限非负数；计数器不允许负增量。
- 默认使用私有 CollectorRegistry，避免多个平台实例或测试共用进程全局注册表造成重复注册冲突。

该适配器解决的是应用内指标的生产导出后端，不代表 Prometheus 服务发现、抓取凭据、远端存储或告警通知已部署。生产部署仍需为抓取身份配置最小权限，并在内网或受控代理后暴露端点。
