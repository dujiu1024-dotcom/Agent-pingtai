# 租户配额、并发与成本归集实现说明

- 关联：总控 #4 / 子任务 #17
- 当前阶段：领域模型、服务端配额接口、进程内参考实现和 PostgreSQL 持久化结构第一批交付；生产数据库原子预留函数、Gateway/Worker 接线和账单对账仍待完成。

## 1. 强制策略

Run 派发前由可信服务端调用 `QuotaService.reserve_run`，不能读取 Agent 自报的预算或限额作为授权依据。租户不匹配、负数估算、硬 Token/成本/并发超限直接拒绝。软限额只返回告警，不阻断。预留记录与 Run、租户和预算范围绑定。

## 2. 范围维度

预算范围支持 tenant、project、agent、model。租户级和模型级是当前参考适配器直接覆盖的维度；项目/Agent 级的实际归集和多维度同时扣减，需要生产 QuotaStore 在同一事务内锁定所有适用预算行，全部检查通过后再写预留，避免部分成功。

## 3. 成本账本

`platform_usage_ledger` 保存 Run、模型、项目、Agent、任务、Token、工具调用、运行时长、存储量、价格卡版本、成本和来源。成本来源区分 estimated、provider_reported、reconciled。账本禁止 UPDATE/DELETE，差异通过对账表新增记录，不覆盖原始事件。

## 4. 并发控制

`hard_concurrency` 由活跃预留数表示。每个 Run 在派发前先预留，完成后结算或释放。生产实现必须用 PostgreSQL 事务与预算行锁，或同等强一致原子机制；不能用各 Worker 本地计数。

## 5. 数据库约束

迁移 `012_tenant_quotas_cost.sql` 增加预算、预留、用量账本和账单对账表。当前迁移提供 append-only 触发器、原子 reserve/settle/release SQL 函数和必要索引。SQL 函数通过锁定预算行串行化同一预算范围的预留；应用侧仍需实现 PostgreSQL QuotaStore 并统一接线。
