# 智能体平台开源组件选型

- 版本：v1.0
- 日期：2026-11-15
- 原则：优先复用成熟组件，保持供应商可替换；新增依赖必须有明确收益和 PoC

## 1. 已冻结组件

| 领域 | 组件/方案 | 采用边界 |
|---|---|---|
| 工作流 | LangGraph | 显式有状态工作流、分支、检查点、人工中断 |
| Agent 执行 | Harness Adapter | 适配成熟开源执行引擎；不自研执行循环 |
| 多专家协作 | Hybrid Blackboard（平台领域实现） | 这是平台协作协议，不用自由聊天替代 |
| 工具协议 | MCP SDK | 协议适配；授权、审批和审计仍由 Tool Gateway |
| 技能描述 | Agent Skills 开放格式 | 目录/元数据/指令标准；平台自行治理加载和权限 |
| 主数据库 | PostgreSQL 15+ | 业务事实源、事务、JSONB、全文检索 |
| 向量 | pgvector | 与租户/文档 ACL 联合检索 |
| 事件分发 | Redis Streams | 只做唤醒；Outbox/Receipt 保证可靠投递 |
| 可观测 | Langfuse 自托管 | Trace/Generation/成本；保留替换适配层 |

## 2. 推荐补充组件（PoC 后引入）
- 文档解析：优先评估 Docling；对格式覆盖/部署资源不足的文件类型，再评估 Unstructured。扫描件 OCR 作为独立能力适配，不将 OCR 绑定到核心服务。
- 检索：PostgreSQL Full Text Search + pgvector 混合召回；Rerank 使用独立接口，可接本地模型或外部兼容服务。
- 对象存储：优先 S3 兼容接口；开发环境可用 MinIO，生产环境按部署环境选择兼容服务。
- API：FastAPI（若当前项目 API 框架已有成熟基础则优先沿用，避免重复引入）。
- 数据访问：沿用现有 SQL/迁移体系，除非复杂度证明确有 ORM 收益；迁移工具必须支持版本化和事务边界。
- 认证：先定义 OIDC/OAuth2 兼容边界；具体 IdP 依据部署环境选择，不自研密码学和身份协议。
- 沙箱：优先评估容器隔离与 gVisor/Firecracker 等强化隔离选项；不得把普通 Python Handler 包装误认为沙箱。

## 3. Harness 评估矩阵
DeepSeek Harness 与 Strands Agents 作为候选，不在未验证前成为唯一 Runtime。统一任务集对比：
1. 工具调用正确率、工具白名单和越权拒绝。
2. 流式、取消、超时、重试、异常传播。
3. 上下文管理、压缩、长任务和多轮状态。
4. 结构化输出、Schema 修复、多模态。
5. 检查点、恢复和运行回放。
6. 质量人工评分、Token、延迟、成本。
7. 执行隔离、网络/文件/进程/凭据边界。
8. 许可证、活跃度、维护成本和升级兼容性。

选型必须提供同任务可复现结果、限制清单和 ADR。不能只依据 README 功能列表或一次成功运行。

## 4. 不引入的重复能力
- 不同时引入多个工作流引擎。
- 不引入第二套消息队列取代 Redis Streams。
- 不因 RAG 便利性直接引入完整 LangChain 作为核心抽象层；采用小而清晰的 Provider/Parser/Retriever/Reranker 接口。
- 不自行维护模型密钥或自建身份协议。
- 不将单一云模型供应商 SDK 暴露到领域层。

## 5. 依赖治理
每个新增组件记录：用途、许可证、版本策略、维护活跃度、部署资源、数据出境、故障模式、替代方案、PoC 结果。锁定版本并进行漏洞扫描；升级需回归关键契约测试。
