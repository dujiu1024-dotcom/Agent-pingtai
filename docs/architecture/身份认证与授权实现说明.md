# 身份认证与授权实现说明

- 版本：v1.0
- 日期：2026-11-15
- 关联：Issue #6；PostgreSQL migration 005
- 状态：核心认证、RBAC、API 凭据和已注册用户邀请接受流程已实现；HTTP 接入、账户注册激活和服务身份认证仍待后续交付

## 1. v1 身份策略

1. 用户是全局身份主体，可加入多个租户；Membership 决定用户是否能进入某个租户。
2. v1 使用邀请/管理员预置账户的本地邮箱+密码登录，不开放公开自助注册。
3. 认证凭据与授权关系分离：User 验证“你是谁”，Tenant Membership 验证“你是否属于该租户”，RoleBinding 决定“你能对哪个资源做什么”。
4. 登录产生租户范围的 opaque session token；数据库只保存 SHA-256 token hash，不保存原始 token。
5. 每次请求重新读取用户、租户成员状态；权限在每次授权时动态查询，不把角色/权限长期固化在 session token 中。
6. OIDC/企业 SSO 通过 External Identity Adapter 扩展；当前只建立外部身份绑定表，不宣称已完成 OAuth/OIDC 流程。

## 2. 认证与会话

### 2.1 密码策略
- 使用 Python 标准库 scrypt；参数随 hash 一起存储，当前 N=32768、r=8、p=1、输出 64 bytes、随机盐 16 bytes。
- 最短 12 字符，最长 1024 字符；验证使用常量时间比较。
- 数据库只存编码后的 password_hash；禁止明文密码进入日志、审计和模型上下文。
- 密码重置、MFA、登录失败限流和异常登录风控尚未接入，需在安全治理阶段补齐。

### 2.2 Session
- 默认有效期 12 小时；应用服务允许配置，但不得超过 30 天。
- token 由密码学安全随机源生成；数据库只存 SHA-256 摘要。
- Session 绑定 (tenant_id, user_id)，复合外键确保必须存在租户成员关系。
- 用户停用、成员关系暂停/退出、Session 过期或撤销，下一次认证立即失败。
- Logout 对单个 Session 软撤销；管理员可后续扩展按用户/租户批量撤销。
- 当前服务返回 opaque token；浏览器端 HttpOnly/Secure/SameSite Cookie、CSRF、防重放和跨站策略应由 HTTP/API 适配层实现，不把 token 放 URL。

### 2.3 错误语义
- 未知用户、密码错误、非租户成员使用一致的认证失败响应，避免账号枚举。
- 资源授权默认拒绝；权限查询失败不得降级为放行。
- Session 只标识用户和租户，不携带角色声明；权限变更无需等待 JWT 过期。

## 3. 租户与组织结构

| 对象 | 表 | 约束 |
|---|---|---|
| User | platform_users | 全局 user_id；email_normalized 全局唯一 |
| 外部身份 | platform_external_identities | provider + provider_subject 唯一，一个用户可关联多个 IdP 身份 |
| 租户成员 | platform_tenant_memberships | (tenant_id,user_id) 复合主键 |
| 组织 | platform_organizations | (tenant_id,organization_id) 复合主键 |
| 组织成员 | platform_organization_memberships | 必须先是租户成员 |
| 团队 | platform_teams | 租户内唯一 |
| 团队成员 | platform_team_memberships | 必须先是租户成员 |
| 项目 | platform_projects | 租户内 project_id、slug 唯一；可归属组织 |
| 工作空间 | platform_workspaces | 必须属于同租户项目 |
| 项目成员 | platform_project_members | 必须先是租户成员 |

所有跨实体引用使用包含 tenant_id 的复合外键。应用层查询还必须显式携带 Principal.tenant_id；不能用前端过滤替代租户隔离。

## 4. RBAC 与资源级授权

### 4.1 模型
- Permission：稳定的权限键，如 `project.read`、`agent.run`、`identity.role.manage`。
- Role：租户内角色，可包含多个 Permission。
- RoleBinding：将 Role 绑定给 user/team/service_account/agent，并限定 resource_type/resource_id。
- Resource scope：支持 tenant、organization、project 等资源范围；当前服务实现精确资源、租户继承，以及 Project 对所属 Organization 的继承。
- Team 角色通过有效的 platform_team_memberships 解析；离开/暂停团队后不再继承团队权限。
- ProjectMember 是成员关系，不自动等价于授权；仍需有效 RoleBinding。

### 4.2 授权执行规则
1. 从已认证 Principal 取得 tenant_id/user_id，不接受模型或请求体覆盖。
2. 对每次资源操作执行授权查询，校验 tenant、subject、resource scope、permission_key 和绑定状态。
3. 用户直接绑定与有效团队绑定均可授权；租户级绑定可继承到租户资源，组织级绑定可继承到所属项目。
4. 未匹配任何有效绑定即拒绝；撤销 RoleBinding 后下一次查询立即生效。
5. 角色授予/撤销操作本身需要 `identity.role.manage` 权限。
6. RoleBinding 新增/撤销与 platform_identity_audit 记录在同一 PostgreSQL 事务提交；审计失败时权限变更回滚。
7. 角色授予和邀请发放执行权限委派上限校验：发起人只能委派其当前在租户级已拥有的权限；检查与写入处于同一事务，避免检查后撤权的竞态。

### 4.3 当前边界
- 当前 Postgres 授权查询支持 user/team 两类主体；service_account/agent 的角色绑定数据结构已预留，但服务身份的认证与授权解析尚未完成。
- 组织级授权继承目前覆盖 Project；Workspace、Agent、Tool、KnowledgeBase、File、Conversation、Task、Run 等资源需在各模块 Repository 接入统一授权端口。
- Permission 目录、每租户默认角色初始化和租户 Owner bootstrap 流程需由租户管理用例补齐；当前不通过隐式“默认管理员”绕过 RBAC。

## 5. 旧系统 users 表迁移映射

旧 SQLite migration v16 的 `users(open_id,name,role,projects,console_token,created_at)` 只用于迁移输入，不作为新身份源：

| 旧字段 | 新平台处理 |
|---|---|
| open_id | 作为外部身份候选标识；必须识别其真实提供方后写入 platform_external_identities，不直接当 user_id |
| name | 映射到 platform_users.display_name |
| role | 经人工确认的角色映射表转换为 platform_roles + platform_role_bindings；不按旧字符串直接授予新权限 |
| projects | 拆分并校验项目归属，转换为 platform_project_members + 项目级 RoleBinding |
| console_token | 不迁移明文；全部作废并要求重新登录/签发新凭据 |
| created_at | 保留为迁移来源元数据，不回写为新用户创建时间，除非迁移审计明确需要 |

迁移前需对旧用户去重、核实 open_id 来源、核对项目归属与角色含义。无法确认身份归属的记录进入待人工认领队列，不自动合并账户。

## 6. 代码实现清单

- `agent_platform/identity/models.py`：UserRecord、SessionRecord、Principal、IssuedSession、ResourceRef、IssuedApiCredential、AuthenticatedApiCredential、InvitationRecord。
- `agent_platform/identity/security.py`：scrypt 密码哈希、opaque token 生成和 token digest。
- `agent_platform/identity/protocols.py`：IdentityRepository 端口。
- `agent_platform/identity/service.py`：login、authenticate、logout、authorize、grant_role、revoke_role；API 凭据创建/认证/原子轮换/撤销/Scope+RBAC 双重校验；邀请创建/邮箱绑定接受。
- `agent_platform/identity/postgres.py`：PostgreSQL 实现；会话、API 凭据和授权查询按 tenant_id 限定；角色授予/撤销、API 凭据撤销/轮换和邀请创建/接受与审计同事务；角色委派执行权限上限校验。
- `agent_platform/identity/bootstrap.py`：对已存在租户执行一次性 Owner 初始化，原子创建首位用户、成员关系、tenant_admin/member/viewer 角色、默认权限和审计记录；拒绝重复初始化。
- `agent_platform/storage/postgres/005_identity_tenant_auth.sql`：身份、租户成员、组织/团队/项目、RBAC、Session、API 凭据、服务账号、Agent 身份、邀请和身份审计结构。
- `tests/test_identity.py`：密码、token、登录、租户成员校验、会话撤销、默认拒绝、角色管理、API 凭据签发/轮换/撤销与邀请单元测试。
- `tests/test_platform_postgres_integration.py`：真实 PostgreSQL 的登录、RBAC、角色撤销、API 凭据 Scope/RBAC、邀请单次接受和审计事务测试。
