# 智能体平台能力全景与需求基线

- 版本：v1.0
- 日期：2026-11-15
- 状态：P0 基线，后续以 ADR 和验收证据迭代
- 关联：总设计 v1.1；Issues #5—#21

## 1. 产品目标与边界
建设一个可配置、可组合、可治理的通用智能体平台。平台提供 Agent 定义与运行、工作流、多专家协作、知识与记忆、工具和 Skills、用户交互、治理、安全、评测和运维能力。业务 Agent 是平台上的应用，不将单个 FDE 工作流固化为平台核心。

本项目采用模块化单体作为默认部署形态。八个能力域是逻辑边界，不是八个微服务。只有在安全隔离、独立扩缩容或团队自治有明确收益时才拆分服务。

## 2. 冻结架构决策
- 多专家协作：Hybrid Blackboard。
- Agent 自主程度：Supervised；高风险副作用需审批。
- 模型配置：Template；Agent 引用模板版本，不硬编码供应商密钥。
- 工作流：LangGraph，负责显式、有状态、可暂停恢复的流程。
- Harness：Adapter 接入成熟执行引擎，不自研执行循环。
- 工具：MCP/内部工具统一经过 Tool Gateway。
- 主数据：PostgreSQL；向量：pgvector；事件唤醒：Redis Streams。
- Outbox 位于 PostgreSQL，是待投递事实源；Redis 不承载唯一业务状态。
- 可观测：Langfuse 自托管适配，平台保留可替换接口。
- 渐进迁移旧 FDE，不推倒重写。

## 4. 跨域横切能力（不可遗漏）
1. 上下文工程：Token 预算、上下文窗口、压缩摘要、引用、隔离、优先级和可追溯性。
2. 委派与协作：子任务、父子运行关系、委派深度/循环限制、结果回传、失败接管。
3. 运行可靠性：租约、幂等、重试、超时、取消、暂停恢复、补偿、死信。
4. 结构化输出：Schema 注册/版本、校验、修复重试、兼容性和失败状态。
5. 多模态：图片/PDF/音频/视频统一输入输出接口，按 Runtime 能力声明启用。
6. Prompt 治理：模板、版本、变量、测试、灰度、回滚、运行快照。
7. 插件扩展：安装、依赖锁定、授权、隔离、版本兼容、卸载清理。
8. 人机协同：补充上下文、编辑草稿、反馈、重新执行、接管和审批。
9. 数据治理：数据分级、保留、归档、导出、删除、脱敏、审计与法律保留。
10. 可追溯：结果关联输入、Prompt、模型模板、工具、知识片段、代码版本和审批。
11. 国际化：租户时区、语言、日期/数字格式；不将服务端 UTC 时间与用户展示时区混用。
12. 开放集成：API 版本、认证、限流、幂等、Webhook、SDK、连接器同步游标。

## 5. 统一状态标记
- 已有可复用：已有实现和测试，可通过契约接入。
- 已有需改造：有局部实现，但不满足平台级边界或治理。
- 需新增设计：职责、实体、接口或验收条件尚不明确。
- 需开发：设计明确但代码未完成。
- 暂缓：非首期必须，需记录理由和重新评估条件。

状态必须附代码/文档证据，不得因存在表或类名就标记为“已完成”。存储底座不等于产品能力，例如 pgvector 不等于知识库，Blackboard 不等于 Memory 或 RAG。

## 6. 非目标
- 不将八个能力域拆成八个微服务。
- 不自研模型推理/工具调用循环。
- 不以 Agent 自由聊天替代 Blackboard 协作。
- 不让 Agent 直接访问数据库、Redis、宿主机或任意网络。
- 不在新平台验收前删除旧 FDE、飞书、SQLite 功能。
- 不在缺少基准和安全验证时锁定单一 Harness 或模型供应商。
