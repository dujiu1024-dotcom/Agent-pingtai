# 智能体平台新旧系统迁移方案

- 版本：v1.0
- 日期：2026-11-15
- 原则：渐进迁移、单一写入方、可校验、可回滚

## 1. 迁移总原则
1. 旧 FDE 系统在新平台达到对应能力验收前继续运行。
2. 新功能优先进入 agent_platform；新模块不得反向依赖旧单体。
3. 每类数据在任一时刻只有一个权威写入方；禁止双主写。
4. 先定义契约和映射，再迁移数据；先影子读校验，再切读写。
5. 所有迁移可重复执行，使用稳定源 ID、批次 ID、内容哈希和差异报告。
6. 迁移前备份；切换失败按预案回滚到旧写入方。

## 2. 存量资产处置建议

| 资产 | 当前职责 | 目标处置 | 约束 |
|---|---|---|---|
| agency.py / boss.py | Agent 调度与业务入口 | Adapter 逐步迁移到 Application/Orchestration | 暂不删除 |
| db.py / agency.db | SQLite 主业务库 | 保持旧系统权威；按实体分批导出到 PostgreSQL | 禁止双主写 |
| memory.py / wm_session | 工作记忆 | 映射到 MemoryService 前先区分会话态/长期态 | 不直接全量灌入 |
| vectors.py / embeddings | Embedding 与向量检索 | 复用算法/供应商适配经验，重建统一 Knowledge 索引 | ACL 与文档版本必须补齐 |
| conversation.py / conversations | 多轮对话 | Adapter 过渡到 Conversation/Message | 保留原始消息和来源 ID |
| gui.py / console.html | 旧控制台 | 保持可用；新平台独立 UI | 不在首期替换旧入口 |
| feishu_bot.py / listener.py | 飞书接入 | 作为 Connector/Channel Adapter | 连接器凭据独立管理 |
| browser.py | 浏览器能力 | 通过受控 Tool Adapter 接入 | 禁止 Runtime 直连浏览器 |
| policy.py | 旧策略/模型选择 | 逐项映射到 Policy/Model Template | 先比对行为再切换 |
| publisher.py | 发布适配空实现 | 评估后接入 Connector/Tool Registry | 不假设已具备发布能力 |

## 3. 数据迁移清单
- 用户/身份：旧 users 记录需映射身份主体；不得把飞书 open_id 当作全局用户主键。
- 项目/客户/任务：映射 Tenant/Project/Task，保留原始业务 ID 和来源。
- 对话：映射 Conversation/Message，保留发送者、时间、渠道和附件关系。
- 工作记忆：先分类、去重、确定保留期与用户确认策略，再迁移。
- 文档/向量：以 DocumentVersion 为单位重建 Chunk/Embedding；旧向量不得在缺少模型/维度/源版本元数据时直接复用。
- 文件：迁移对象本体、元数据、哈希、权限和引用；路径不直接暴露为平台 URL。
- 审批/审计：保留历史记录只读导入，原始时间和操作者字段不覆盖。
- 凭据：不迁移明文；要求重新授权或迁移到 Secret Manager 引用。

## 4. 切换步骤
1. 盘点并冻结源端 schema/数据快照。
2. 建立字段映射、数据分类、数据权限和去重规则。
3. 完成全量导出与导入；记录迁移批次和源/目标数量。
4. 执行双读差异校验（只读，不双写），核对主键、关联、哈希、权限。
5. 小范围启用新平台读路径；观察错误、性能和数据缺失。
6. 明确切换窗口后暂停旧写入，完成增量尾批。
7. 将新平台设为唯一写入方，观察期内保留回滚能力。
8. 验收通过后按保留策略归档旧数据；删除需单独审批。

## 5. 删除、导出和保留
用户/租户删除请求必须识别主库、对象存储、向量索引、缓存、检索日志、连接器副本和备份中的数据。明确软删除窗口、物理删除时限、备份过期周期、法律保留例外和删除证明。
导出应包含结构化数据、文件清单、来源和时间元数据；敏感凭据不导出。
